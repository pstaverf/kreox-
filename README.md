# Kreox Bot

VK-бот на Node.js 24 LTS, TypeScript 7.0.2, vk-io 4.10.1 и официальном драйвере mongodb 7.7.0. Зависимости зафиксированы в `package-lock.json`.

## Запуск

```sh
npm ci
cp .env.example .env
```

Заполните `.env` локально:

| Переменная | Значение |
| --- | --- |
| `VK_TOKEN` | Токен сообщества с правами на сообщения и Long Poll |
| `VK_GROUP_ID` | Положительный числовой ID сообщества, без минуса |
| `MONGODB_URI` | Строка подключения MongoDB Atlas |
| `MONGODB_DB` | Имя отдельной базы этого бота, например `kreox` |

Секреты не нужно отправлять в чат или добавлять в Git. Настройте доступ к кластеру в Atlas Network Access и пользователя БД с правами `readWrite` на выбранную базу. При старте проверяются переменные, подключение, поддержка транзакций и создаются индексы. Standalone MongoDB не поддерживается: нужен replica set или Atlas.

В сообществе включите сообщения, Bots Long Poll API версии 5.199 и событие `message_new`. Используются обычные текстовые кнопки, не callback-кнопки; событие `message_event` не требуется. Для бесед добавьте сообщество и убедитесь, что VK доставляет ему `message_new` из беседы.

```sh
npm run typecheck
npm test
npm run build
npm start
```

`npm start` автоматически пересобирает исходники через `prestart`, чтобы не запускать устаревший `dist`, и загружает `.env`, если файл существует; переменные окружения хостинга также поддерживаются. При ошибке конфигурации или подключения запуск завершается с ненулевым кодом. SIGINT и SIGTERM останавливают получение событий, дожидаются текущих обработчиков и закрывают MongoDB.

## Что реализовано

- Аккаунт создаётся при первом сообщении в личке или первой распознанной команде в беседе. В личке отправляются приветствие и основная клавиатура; в беседах ответы всегда без клавиатуры.
- Профиль, меню, инвентарь и возврат в профиль. Город — синяя кнопка с отдельным текстом стройки, донат — зелёная.
- У всех неразработанных разделов, включая управление предметом, ответ `⚙️ В разработке…`.
- Семь последовательных бонусов из ТЗ, получение раз в четыре часа от последнего успешного получения.
- При перерыве **от 24 часов с последнего успешного получения** серия начинается с первого бонуса. Неудачное нажатие во время ожидания не продлевает серию и не сдвигает таймер.
- После седьмого бонуса следующий доступный бонус — первый. Если не получить бонус за 24 часа, серия также сбросится.
- Седьмой бонус выдаёт один кейс «Ждун». Открытие кейса пока не реализовано.
- Предметы нумеруются отдельно у каждого игрока с 1 по порядку получения. Инвентарь отсортирован по этому ID. В личке страницы по 8 предметов с навигацией при необходимости: клавиатура не превышает 10 строк.
- Первые 50 регистраций получают ID 0–49. Далее выбирается случайный свободный ID 51–9999; ID 50 намеренно пропущен. При исчерпании диапазона новые регистрации отказываются без частичной записи игрока и без переиспользования чужого ID.

## Майнинг, рейтинги и рефералы

### Майнинг

Ферма по умолчанию выключена, скорость `0,100₿/час`. Запуск длится ровно 6 часов, повторный запуск активной фермы не продлевает срок. Добыча вычисляется лениво по времени MongoDB: отдельного таймера на игрока нет, перезапуск не меняет результат. Ферма после завершения не перезапускается сама.

В `mining` хранятся `rate`, `balance`, `remainder`, `level`, `upgradeCost`, `updatedAt`, `activeUntil`. Деньги и скорость — целые сатоши. Произведение скорости на миллисекунды вычисляется через BigInt, остаток деления на миллисекунды часа сохраняется, поэтому частые действия не увеличивают доход и не теряют доли сатоши. В БД остаются безопасные целые Number. При достижении `Number.MAX_SAFE_INTEGER` накопление сверх лимита прекращается; профильный баланс не переполняется.

На экране фермы скорость и баланс показываются с запятой и ровно тремя знаками после неё. Лишние знаки отбрасываются только при отображении, реальные сатоши не списываются. Снять можно от `1,000₿`; переводится весь накопленный баланс, вместе с обнулением фермы в той же транзакции. При нехватке места в кошельке вся операция отклоняется.

Улучшение оплачивается биткоинами **профиля**, не балансом фермы. Цены строго по списку: `0,002; 0,005; 0,008; 0,014; 0,023; 0,033; 0,041; 0,049; 0,059; 0,078; 0,098; 0,109; 0,127; 0,142; 0,170; 0,203₿`. Затем предыдущая цена умножается на 6/5 и округляется вверх до `0,001₿`: `0,244; 0,293; 0,352` и далее.

Прибавка равновероятно выбирается из диапазона `0,015–0,080₿/час` с шагом `0,001` через `crypto.randomInt`. Подтверждение содержит только ожидаемый уровень: цена и прибавка не берутся из payload. Два подтверждения одного предложения не покупают два уровня. Уже накопленная добыча считается по прежней скорости, новая скорость действует с момента покупки; срок работы не продлевается. Согласованная очень низкая стоимость улучшений сохранена без изменения экономики.

### Рейтинги

Кнопка «Рейтинг» открывает топ KC. Доступны KC, биткоины, скорость майнинга, евро, число приглашённых, репутация и украденные KC. Показываются до 20 игроков и собственная позиция среди **всех** игроков. При равенстве показателя выше игрок с меньшим ID аккаунта. Упоминания закрываются корректным `]`. Рейтинги считываются в одном снимке транзакции; выборка ограничена и использует соответствующий индекс.

Механики краж не добавлены: `stolenKC` пока равен 0 и означает общую сумму украденных KC. Реферальный счётчик растёт только при успешной первой регистрации по ссылке. Топ майнинга сравнивает скорость фермы независимо от того, включена ли она сейчас.

### Рефералы

В профиле кнопки `👤 Реф | 🎒 Инвентарь`, ниже `📕 Меню`. При первом открытии реферального раздела `utils.getShortLink` сокращает адрес `https://vk.me/clubGROUP_ID?ref=kreox_VK_ID` до `vk.cc`. Необязательный параметр `private` не передаётся: на рабочем токене сообщества VK вернул код `100` с упоминанием `private` даже при значении `1`. Статистика короткой ссылки публичная по умолчанию; для учёта рефералов она не используется. Точное ограничение VK для этого параметра с токеном сообщества не подтверждено официальной документацией; успешное сокращение без него требует проверки на рабочем VK. Ссылка кешируется в документе игрока. Вызов VK всегда вне транзакции. При ошибке сокращения лог `referral_short_link` содержит метод, код и только безопасную подсказку `private`/`url`, если она есть в сообщении ошибки, без полного сообщения и параметров запроса.

Сам клик по ссылке бот не видит: атрибуция возможна только когда VK передал `ref` в первом входящем сообщении незарегистрированного игрока в личке. `referrerId` из payload игнорируется; самоприглашения, несуществующие пригласившие и уже зарегистрированные аккаунты не дают награды. Дополнительных требований к новичку не добавлено. Уникальность человека за несколькими VK ID не проверяется и без отдельной согласованной антифрод-механики не гарантируется.

Регистрация новичка, `15.000 KC`, увеличение числа приглашённых, один кейс «Реферальный», личный ID предмета и запись уведомления объединены одной транзакцией. Новичок получает обычное приветствие. При переполнении награда не применяется частично: транзакция регистрации по такой ссылке откатывается.

Уведомление пригласившему отправляется только после коммита. Один обработчик очереди стартует вместе с ботом; состояние и время повторов хранятся в MongoDB. Пока действует lease на 120 секунд, другой экземпляр не может захватить ту же запись; постоянный `random_id` защищает повторную отправку после сбоя. После перезапуска незавершённая запись доступна после истечения lease. Временные ошибки повторяются с задержкой от 5 секунд до часа; закрытые личные сообщения и постоянный запрет отправки фиксируются как `failed`, награда остаётся выданной. Управления и открытия реферального кейса пока нет.

## Промокоды и город

`🏷 Промо` открывает `🎁 Меню промокодов:` с кнопками создания, активации (зелёная) и списка своих промокодов. Система промокодов работает в личке: текст беседы не может продолжить или подтвердить личный черновик.

Создание проходит по шагам: валюта `KC | 💶 | 💠`, название, награда за одну активацию, количество, инлайн-кнопка `✅ Подтвердить`. Это текстовая inline-кнопка с payload, не callback; дополнительных событий VK не требуется. Данные черновика хранятся в `players.promoDraft`, а не в памяти процесса. «Назад» отменяет черновик и возвращает в меню промокодов; переход в другие разделы отменяет черновик. Во время ввода свободного текста названия не превращаются в команды разделов; `📕 Меню` и `↩️ Назад` остаются навигацией. Подтверждение действует только для текущего черновика его владельца: токен привязан к событию ввода количества, старые и чужие кнопки не создают промокод. Нажатие подтверждения не берёт суммы, валюту, владельца или количество из payload.

Названия содержат 5–20 Unicode-кодовых точек, регистр учитывается: `Подарок` и `подарок` различаются. Краевые пробелы отбрасываются; переносы строк, управляющие символы и некорректные Unicode-последовательности запрещены. Название глобально уникально и остаётся занятым после исчерпания активаций; удаления, возврата оставшихся средств и переименования не добавлено.

Суммы и количество принимаются только целыми числами. Точка может разделять тысячи (`10.000` = 10000), но не дробную часть. Минимальная награда: 10.000 KC, 5 евро или 5₿; минимум 5 активаций. На экране минимума евро сохранён заданный символ `💴`, награда и кошелёк используют `💶`. В БД используются существующие масштабы валют: сотые KC и евро, сатоши BTC. Полная стоимость `награда × количество` вычисляется через BigInt с проверкой безопасного целого диапазона и списывается с **кошелька создателя** при подтверждении. До подтверждения списаний нет; при нехватке денег промокод не публикуется.

Один игрок может получить награду конкретного промокода только один раз; создатель не может активировать свой. Проверяются наличие, остаток, повторная активация и верхняя граница кошелька. Списание стоимости и публикация промокода объединены с ответом и дедупликацией одной транзакцией; так же атомарны уменьшение остатка, награда и запись активации. Ошибка не расходует активацию или деньги частично. Повтор сообщения возвращает сохранённый ответ и `random_id`.

`📖 Мои промо` показывает только промокоды владельца, включая исчерпанные: название, оставшиеся активации, награду, пустую строку между записями. Чтобы не превысить лимит VK и не выполнять неограниченные запросы, список выдаётся по 10 записей, при необходимости с кнопкой `▶️`; «Назад» возвращает в меню промокодов. Выборка использует индекс владельца и курсор по названию без неограниченного `skip`.

`🏙️ Город` отвечает ровно:

```text
🏙️ Стройка уже идёт!

💫 Скоро город будет сиять раньше остальных…
```

## Допущения

- Начальные KC, евро, биткоины, репутация и выполненные задания — 0; инвентарь пуст. Пока задания не разработаны, показывается `0/0 [0.00%]`.
- Имя — имя пользователя из VK при регистрации. Пользовательские ники и смена имени ещё не реализованы. Опасные символы разметки и управляющие символы удаляются, массовые упоминания отключены через `disable_mentions`.
- В беседах `я` показывает профиль, `и`, `инв` и `инвентарь` показывают весь небольшой инвентарь одним текстом без кнопок и страниц. Регистр команд не важен. Пустая клавиатура в ответе убирает старые кнопки предыдущих версий бота. Посторонний текст игнорируется; известные текстовые команды разделов также обрабатываются без клавиатуры. Если инвентарь превышает предел одного сообщения, бот прямо сообщает об ограничении и предлагает личку, не теряя и не обрезая предметы. Аккаунт, ферма и бонус общие для всех бесед и личных сообщений; владелец определяется только по отправителю события VK.
- Для одного сообщества запускается один получатель Long Poll. Целостность экономики и дедупликация обеспечиваются MongoDB, а не памятью процесса.
- Каждое исходное сообщение получает сохранённый положительный сквозной `random_id` из БД; повторные доставки используют его снова, независимо от беседы. Диапазон — 1–2147483647; при его исчерпании операция откатывается. Отрицательные случайные ID зарезервированы для сообщений об ошибке обработки.
- VK может не доставить ответ после успешного коммита, например при закрытых сообщениях или остановке процесса. Начисление не теряется и не повторяется; состояние видно в профиле. Дедупликация хранит готовый ответ, но автоматической гарантированной доставки после перезапуска нет. Для обычных ответов отдельной очереди доставки нет. Для реферальных уведомлений реализована постоянная очередь `notifications`: награда не теряется при недоставке уведомления.

## Данные и инварианты

У зарегистрированного игрока нет дополнительного запроса проверки существования перед транзакцией. Имя нового игрока запрашивается у VK только после обнаружения отсутствующего аккаунта и вне транзакции; затем регистрация повторно проверяет состояние в БД.

Бизнес-логика в `src/services` не зависит от vk-io. Обработчики и клавиатуры — `src/handlers`, MongoDB — `src/repositories`, типы — `src/types`, параметры экономики — `src/config/game.ts`, пользовательские тексты — `src/services/texts.ts`.

| Коллекция | Назначение и индексы |
| --- | --- |
| `players` | `_id` — VK ID, стандартный уникальный индекс; `accountId` — отдельный уникальный индекс. Для каждого рейтинга составной индекс `{ показатель: -1, accountId: 1 }`, в том числе `mining.rate`, `referrals`, `stolenKC` |
| `inventory` | `_id` — пара VK ID и ID предмета; уникальный составной индекс `{ vkId: 1, itemId: 1 }` для принадлежности, порядка и страниц |
| `notifications` | Уникальный `_id` вида `referral:VK_ID_новичка`; индекс `{ state: 1, nextAttemptAt: 1 }`, состояние отправки, lease и постоянный `random_id` |
| `promos` | Уникальный `_id` — регистрозависимое название; индекс `{ ownerId: 1, _id: 1 }` с бинарным сравнением для списка владельца. Награда, валюта, начальное количество и остаток |
| `promo_redemptions` | Уникальный `_id` из UTF-8 hex названия и VK ID; уникальный индекс `{ promoName: 1, vkId: 1 }`, без TTL |
| `counters` | Стандартный уникальный `_id`; счётчики `registrations` и `responses`, начальное значение 0 |
| `processed_messages` | Стандартный уникальный `_id`, составленный из ID сообщества, беседы и сообщения внутри беседы; сохранены отправитель и готовый ответ |

KC и евро хранятся целыми сотыми долями, биткоины — целыми сатоши, 100000000 на 1₿. Верхняя граница каждого денежного поля — `Number.MAX_SAFE_INTEGER` в минимальных единицах. Начисления проверяют верхние границы внутри фильтра атомарного `$inc`. Форматирование выполняется через BigInt без округления денежных значений через float; в MongoDB значения остаются безопасными целыми Number.

Регистрация, выдача ID, начисление бонуса, добавление кейса, увеличение личного ID предмета, выдача `random_id` и запись обработанного события выполняются в транзакциях `withTransaction` с `majority` и `snapshot`. Время бонусов и майнинга берётся из MongoDB через `$$NOW`, не из времени клиента VK или часов отдельного процесса. Все вызовы VK — вне транзакции.

Повторная доставка сообщения возвращает сохранённый результат. Одновременные разные сообщения не обходят кулдаун. При ошибке внутри транзакции не остаётся частично выданного бонуса, потерянного кейса или пропущенного последовательного ID регистрации. Ошибки уникальных индексов обрабатываются отдельно, с ограниченными повторами. Записи дедупликации не имеют TTL: удаление таких записей разрешило бы повторно применить старое событие после истечения кулдауна.

Для токена сообщества задан лимит 20 API-запросов в секунду с равномерной очередью, без burst. Режим `parallel_selected` объединяет ожидающие отправки `messages.send` в `execute`, до 25 за запрос; остальные методы выполняются отдельно. vk-io повторяет внешнюю ошибку лимита 6 с задержкой и делает до двух повторов транспортных ошибок. Для ошибки 6 отдельной отправки внутри `execute` обработчик делает до двух повторов с задержкой и тем же `random_id`. Используемые вызовы — чтение и отправка с сохранённым `random_id`, поэтому их повтор безопасен. Запрет отправки и недоступность беседы логируются без повторного начисления награды. В лог не передаются текст исключения VK, параметры запроса, токен и URI MongoDB.

При старте выполняется идемпотентная миграция существующих игроков: отсутствующая ферма получает базовые настройки, отсутствующие `referrals` и `stolenKC` получают 0. Имеющиеся балансы, ID, фермы и счётчики не сбрасываются. `referralUrl` сохраняется только после успешного сокращения ссылки. Новых обязательных переменных окружения и зависимостей нет. Коллекции и индексы промокодов создаются при инициализации, отсутствие `promoDraft` у старых игроков означает отсутствие черновика и не требует перезаписи игроков. Интерфейс хранилища `GameStore` дополнен операциями новых систем. Инициализация индексов и счётчиков также идемпотентна; повторный старт не сбрасывает данные. Нельзя удалять или сбрасывать счётчики отдельно от связанных коллекций.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm audit
```

Строгий TypeScript проверяет также тесты, включая `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, неиспользуемые переменные и декларации зависимостей.

Модульные тесты используют транзакционное хранилище в памяти и реальные типы контекста vk-io с подменённым транспортом. Они проверяют тексты, кнопки, числовые границы, повторные и параллельные вызовы, сброс серии, кейсы, точный расчёт майнинга, повторное подтверждение, снятие, рейтинги и ничьи, рефералов, перезапуск отправки уведомлений, откат при сбое, подделку payload, разделение игроков и безопасное логирование. Промокоды проверяются для трёх валют: стоимость, минимумы, Unicode-названия, регистр, уникальность, одноразовая активация, запрет своего промокода, лимиты, инлайн-кнопка, восстановление черновика, страницы списка и полный диалог через обработчик VK.

Для интеграционных тестов укажите `MONGODB_TEST_URI` в локальном `.env` или окружении. Это должна быть **тестовая** MongoDB с replica set и правом создавать и удалять базы `kreox_test_*`. Тест создаёт отдельную случайно названную базу и удаляет только её после завершения:

```sh
npm run test:integration
```

Без `MONGODB_TEST_URI` все три интеграционных набора пропускаются с явной причиной. Тесты проверяют реальные гонки регистрации, бонусов, майнинга и рефералов, индексы, распределение ID, миграцию, рейтинги, lease уведомлений, откат кейса вместе с балансом, дедупликацию и исчерпание диапазона. Отдельный набор проверяет гонки создания одного промокода разными владельцами, последние активации, повторное получение, полный откат списаний и наград, чувствительность к регистру и восстановление подтверждения. Подменённое хранилище не заменяет эти проверки.

Проверка с настоящими VK и Atlas требует токена, подключения к кластеру и доступа к их сетевым адресам; без них такой запуск не подтверждён.

## Администрирование

Команда `/dk` только в беседах удаляет текущую клавиатуру бота и отвечает ровно `Done.`. Доступ разрешён только VK ID `888801846`, список находится в `src/config/admin.ts`. Проверяются отправитель события и тип беседы; данные payload не дают прав. В личке и от других пользователей команда молча игнорируется. Команда не регистрирует администратора и не меняет игровые данные; дедупликация и сохранённый `random_id` используются как у остальных ответов.
