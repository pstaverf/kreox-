# Kreox Bot

VK-бот на Node.js 24 LTS, TypeScript 7.0.2, vk-io 4.10.1 и официальном драйвере mongodb 7.7.0. Зависимости зафиксированы в `package-lock.json`.

## Запуск

```sh
npm ci
cp .env.example .env
```

Заполните `.env` локально:

| Переменная | Значение |
| --- | --- |
| `VK_TOKEN` | Токен сообщества с правами на сообщения и Long Poll |
| `VK_GROUP_ID` | Положительный числовой ID сообщества, без минуса |
| `MONGODB_URI` | Строка подключения MongoDB Atlas |
| `MONGODB_DB` | Имя отдельной базы этого бота, например `kreox` |

Секреты не нужно отправлять в чат или добавлять в Git. Настройте доступ к кластеру в Atlas Network Access и пользователя БД с правами `readWrite` на выбранную базу. При старте проверяются переменные, подключение, поддержка транзакций и создаются индексы. Standalone MongoDB не поддерживается: нужен replica set или Atlas.

В сообществе включите сообщения, Bots Long Poll API версии 5.199 и событие `message_new`. Используются текстовые кнопки с payload, не callback-кнопки; событие `message_event` не требуется. Для бесед добавьте сообщество и убедитесь, что VK доставляет ему `message_new` из беседы.

```sh
npm run typecheck
npm test
npm run build
npm start
```

`npm start` автоматически пересобирает исходники через `prestart`, чтобы не запускать устаревший `dist`, и загружает `.env`, если файл существует; переменные окружения хостинга также поддерживаются. При ошибке конфигурации или подключения запуск завершается с ненулевым кодом. SIGINT и SIGTERM останавливают получение событий, дожидаются текущих обработчиков и закрывают MongoDB.

## Кнопки и текстовый ввод

Каждая кнопка во всех клавиатурах, включая основное меню, профиль, бонус, майнинг, рейтинги, навигацию, промокоды и предметы, содержит payload с командой и необходимыми параметрами. Действие определяется по проверенному payload, а не по подписи. Сообщение `🎁 Бонус` без payload или с посторонними параметрами не начисляет награду; то же правило действует для других кнопочных действий. В личке вне диалога такой текст получает обычный ответ нераспознанного раздела и обновлённую основную клавиатуру, в беседе игнорируется. Старые кнопки без payload нужно заменить новой клавиатурой, полученной от бота.

Текст сохраняется для регистрации и приветствия при первом сообщении, админских команд, алиасов `я`, `и`, `инв`, `инвентарь` в беседах, а также ввода названий, сумм, получателей, количества и отмены в активных диалогах. Внутренний сервис по-прежнему принимает типизированные команды; проверка внешнего формата происходит в обработчике и парсере.

Payload **не является защитой от автоматизированного клиента**: клиент может сформировать такое же сообщение с payload без ручного нажатия. Секретов в payload нет; отправитель, доступ, цены, баланс, владение, кулдауны и повторная обработка проверяются сервером. Кулдаун бонуса остаётся прежним — четыре часа. Дополнительных антибот-механик или изменений экономики не добавлено.

В ответе бонуса ровно одна пустая строка после заголовка, между наградами — одиночные переносы. В майнинге одна пустая строка отделяет статус от компактного блока добычи, баланса и оставшегося времени. Профиль остаётся компактным: в ЛС восемь строк с датой регистрации, в беседах семь строк без новой строки возраста.

## Что реализовано

- Аккаунт создаётся при первом сообщении в личке или первой распознанной команде в беседе. В личке отправляются приветствие и основная клавиатура; в беседах ответы всегда без клавиатуры.
- Профиль, меню, инвентарь и возврат в профиль. Город — синяя кнопка с меню банка, директора и казино; донат — зелёная.
- У оставшихся неразработанных разделов ответ `⚙️ В разработке…`.
- Семь последовательных бонусов из ТЗ, получение раз в четыре часа от последнего успешного получения.
- При перерыве **от 24 часов с последнего успешного получения** серия начинается с первого бонуса. Неудачное нажатие во время ожидания не продлевает серию и не сдвигает таймер.
- После седьмого бонуса следующий доступный бонус — первый. Если не получить бонус за 24 часа, серия также сбросится.
- Седьмой бонус выдаёт один кейс «Ждун». Открытие, подарки и продажа кейсов описаны ниже.
- Одинаковые предметы в инвентаре объединяются в одну строку с общим количеством: `(4 шт.)`. ID строки — наименьший ID принадлежащего игроку экземпляра этого типа; кнопка открывает карточку типа. Сортировка — по ID строки. В личке страницы по 8 типов с навигацией при необходимости: клавиатура не превышает 10 строк.
- Первые 50 регистраций получают ID 0–49. Далее выбирается случайный свободный ID 51–9999; ID 50 намеренно пропущен. При исчерпании диапазона новые регистрации отказываются без частичной записи игрока и без переиспользования чужого ID.

## Майнинг, рейтинги и рефералы

### Майнинг

Ферма по умолчанию выключена, скорость `0,100₿/час`. Запуск длится ровно 6 часов, повторный запуск активной фермы не продлевает срок. Добыча вычисляется лениво по времени MongoDB: отдельного таймера на игрока нет, перезапуск не меняет результат. Ферма после завершения не перезапускается сама.

В `mining` хранятся `rate`, `balance`, `remainder`, `level`, `upgradeCost`, `updatedAt`, `activeUntil`. Деньги и скорость — целые сатоши. Произведение скорости на миллисекунды вычисляется через BigInt, остаток деления на миллисекунды часа сохраняется, поэтому частые действия не увеличивают доход и не теряют доли сатоши. В БД остаются безопасные целые Number. При достижении `Number.MAX_SAFE_INTEGER` накопление сверх лимита прекращается; профильный баланс не переполняется.

На экране фермы скорость и баланс, а также BTC в профиле/меню, сообщении о снятии и обеих частях рейтинга биткоинов показываются с запятой и ровно тремя знаками после неё (`1,116₿`, `3,711₿`, `0,000₿`). Формат фиксированных наград бонуса и промокодов не меняется. Лишние знаки отбрасываются только при отображении, реальные сатоши не списываются. Снять можно от `1,000₿`; переводится весь накопленный баланс, вместе с обнулением фермы в той же транзакции. При нехватке места в кошельке вся операция отклоняется.

Улучшение оплачивается биткоинами **профиля**, не балансом фермы. Цены строго по списку: `0,002; 0,005; 0,008; 0,014; 0,023; 0,033; 0,041; 0,049; 0,059; 0,078; 0,098; 0,109; 0,127; 0,142; 0,170; 0,203₿`. Затем предыдущая цена умножается на 6/5 и округляется вверх до `0,001₿`: `0,244; 0,293; 0,352` и далее.

Прибавка равновероятно выбирается из диапазона `0,015–0,080₿/час` с шагом `0,001` через `crypto.randomInt`. Подтверждение содержит только ожидаемый уровень: цена и прибавка не берутся из payload. Два подтверждения одного предложения не покупают два уровня. Уже накопленная добыча считается по прежней скорости, новая скорость действует с момента покупки; срок работы не продлевается. Согласованная очень низкая стоимость улучшений сохранена без изменения экономики.

### Рейтинги

Кнопка «Рейтинг» открывает топ KC. Доступны KC, биткоины, скорость майнинга, евро, число приглашённых, репутация и украденные KC. Показываются до 20 игроков и собственная позиция среди **всех** игроков. При равенстве показателя выше игрок с меньшим ID аккаунта. Упоминания закрываются корректным `]`. Рейтинги считываются в одном снимке транзакции; выборка ограничена и использует соответствующий индекс.

`stolenKC` означает общую сумму KC, украденных командой «вор» по подписке из доната. Реферальный счётчик растёт только при успешной первой регистрации по ссылке. Топ майнинга сравнивает скорость фермы независимо от того, включена ли она сейчас.

### Рефералы

В профиле кнопки `👤 Реф | 🎒 Инвентарь`, ниже `📕 Меню`. При первом открытии реферального раздела `utils.getShortLink` сокращает адрес `https://vk.me/clubGROUP_ID?ref=kreox_VK_ID` до `vk.cc`. Необязательный параметр `private` не передаётся: на рабочем токене сообщества VK вернул код `100` с упоминанием `private` даже при значении `1`. Статистика короткой ссылки публичная по умолчанию; для учёта рефералов она не используется. Точное ограничение VK для этого параметра с токеном сообщества не подтверждено официальной документацией; успешное сокращение без него требует проверки на рабочем VK. Ссылка кешируется в документе игрока. Вызов VK всегда вне транзакции. При ошибке сокращения лог `referral_short_link` содержит метод, код и только безопасную подсказку `private`/`url`, если она есть в сообщении ошибки, без полного сообщения и параметров запроса.

Сам клик по ссылке бот не видит: атрибуция возможна только когда VK передал `ref` в первом входящем сообщении незарегистрированного игрока в личке. `referrerId` из payload игнорируется; самоприглашения, несуществующие пригласившие и уже зарегистрированные аккаунты не дают награды. Дополнительных требований к новичку не добавлено. Уникальность человека за несколькими VK ID не проверяется и без отдельной согласованной антифрод-механики не гарантируется.

Регистрация новичка, `15.000 KC`, увеличение числа приглашённых, один кейс «Реферальный», личный ID предмета и запись уведомления объединены одной транзакцией. Новичок получает обычное приветствие. При переполнении награда не применяется частично: транзакция регистрации по такой ссылке откатывается.

Уведомление пригласившему отправляется только после коммита. Один обработчик очереди стартует вместе с ботом; состояние и время повторов хранятся в MongoDB. Пока действует lease на 120 секунд, другой экземпляр не может захватить ту же запись; постоянный `random_id` защищает повторную отправку после сбоя. После перезапуска незавершённая запись доступна после истечения lease. Временные ошибки повторяются с задержкой от 5 секунд до часа; закрытые личные сообщения и постоянный запрет отправки фиксируются как `failed`, награда остаётся выданной. Реферальный кейс можно открывать, дарить и продавать по правилам предметов ниже.

## Промокоды и город

`🏷 Промо` открывает `🎁 Меню промокодов:` с кнопками создания, активации (зелёная) и списка своих промокодов. Система промокодов работает в личке: текст беседы не может продолжить или подтвердить личный черновик.

Создание проходит по шагам: валюта `KC | 💶 | 💠`, название, награда за одну активацию, количество, инлайн-кнопка `✅ Подтвердить`. Это текстовая inline-кнопка с payload, не callback; дополнительных событий VK не требуется. Данные черновика хранятся в `players.promoDraft`, а не в памяти процесса. «Назад» отменяет черновик и возвращает в меню промокодов; переход в другие разделы отменяет черновик. Во время ввода свободного текста названия не превращаются в команды разделов; навигация `📕 Меню` и `↩️ Назад` выполняется только по payload соответствующей кнопки. Подтверждение действует только для текущего черновика его владельца: токен привязан к событию ввода количества, старые и чужие кнопки не создают промокод. Нажатие подтверждения не берёт суммы, валюту, владельца или количество из payload.

Названия содержат 5–20 Unicode-кодовых точек, регистр учитывается: `Подарок` и `подарок` различаются. Краевые пробелы отбрасываются; переносы строк, управляющие символы и некорректные Unicode-последовательности запрещены. Название глобально уникально и остаётся занятым после исчерпания активаций; удаления, возврата оставшихся средств и переименования не добавлено.

Суммы и количество принимаются только целыми числами. Точка может разделять тысячи (`10.000` = 10000), но не дробную часть. Минимальная награда: 10.000 KC, 5 евро или 5₿; минимум 5 активаций. На экране минимума евро сохранён заданный символ `💴`, награда и кошелёк используют `💶`. В БД используются существующие масштабы валют: сотые KC и евро, сатоши BTC. Полная стоимость `награда × количество` вычисляется через BigInt с проверкой безопасного целого диапазона и списывается с **кошелька создателя** при подтверждении. До подтверждения списаний нет; при нехватке денег промокод не публикуется.

Один игрок может получить награду конкретного промокода только один раз; создатель не может активировать свой. Проверяются наличие, остаток, повторная активация и верхняя граница кошелька. Списание стоимости и публикация промокода объединены с ответом и дедупликацией одной транзакцией; так же атомарны уменьшение остатка, награда и запись активации. Ошибка не расходует активацию или деньги частично. Повтор сообщения возвращает сохранённый ответ и `random_id`.

`📖 Мои промо` показывает только промокоды владельца, включая исчерпанные: название, оставшиеся активации, награду, пустую строку между записями. Чтобы не превысить лимит VK и не выполнять неограниченные запросы, список выдаётся по 10 записей, при необходимости с кнопкой `▶️`; «Назад» возвращает в меню промокодов. Выборка использует индекс владельца и курсор по названию без неограниченного `skip`.

`🏙️ Город` открывает `🏙️ Город:` с кнопками директора, банка и казино. Полные правила банка приведены ниже.

## Допущения

- Начальные KC, евро, биткоины, репутация и выполненные задания — 0; инвентарь пуст. Пока задания не разработаны, показывается `0/0 [0.00%]`.
- Имя из VK используется при регистрации; купленный в донате ник заменяет его в новых сообщениях. Опасные символы разметки и управляющие символы удаляются, массовые упоминания отключены через `disable_mentions`.
- В беседах `я` показывает профиль, `и`, `инв` и `инвентарь` показывают весь небольшой инвентарь одним текстом без кнопок и страниц. Регистр команд не важен. Пустая клавиатура в ответе убирает старые кнопки предыдущих версий бота. Посторонний текст и вручную написанные подписи кнопок игнорируются; распознанные payload-команды обрабатываются без клавиатуры. Если инвентарь превышает предел одного сообщения, бот прямо сообщает об ограничении и предлагает личку, не теряя и не обрезая предметы. Аккаунт, ферма и бонус общие для всех бесед и личных сообщений; владелец определяется только по отправителю события VK.
- Для одного сообщества запускается один получатель Long Poll. Целостность экономики и дедупликация обеспечиваются MongoDB, а не памятью процесса.
- Каждое исходное сообщение получает сохранённый положительный сквозной `random_id` из БД; повторные доставки используют его снова, независимо от беседы. Диапазон — 1–2147483647; при его исчерпании операция откатывается. Отрицательные случайные ID зарезервированы для сообщений об ошибке обработки.
- VK может не доставить ответ после успешного коммита, например при закрытых сообщениях или остановке процесса. Начисление не теряется и не повторяется; состояние видно в профиле. Дедупликация хранит готовый ответ, но автоматической гарантированной доставки после перезапуска нет. Для обычных ответов отдельной очереди доставки нет. Для реферальных уведомлений реализована постоянная очередь `notifications`: награда не теряется при недоставке уведомления.

## Данные и инварианты

У зарегистрированного игрока нет дополнительного запроса проверки существования перед транзакцией. Имя нового игрока запрашивается у VK только после обнаружения отсутствующего аккаунта и вне транзакции; затем регистрация повторно проверяет состояние в БД.

Бизнес-логика в `src/services` не зависит от vk-io. Обработчики и клавиатуры — `src/handlers`, MongoDB — `src/repositories`, типы — `src/types`, параметры экономики — `src/config/game.ts`, пользовательские тексты — `src/services/texts.ts`.

| Коллекция | Назначение и индексы |
| --- | --- |
| `players` | `_id` — VK ID, стандартный уникальный индекс; `accountId` — отдельный уникальный индекс. Для каждого рейтинга составной индекс `{ показатель: -1, accountId: 1 }`, в том числе `mining.rate`, `referrals`, `stolenKC` |
| `item_offers` | Уникальный `_id` события подтверждения продажи; индекс `{ buyerId: 1, state: 1, expiresAt: 1 }`. Покупатель, продавец, тип, количество, общая цена, срок и состояние; без TTL |
| `inventory` | `_id` — пара VK ID и ID предмета; уникальный составной индекс `{ vkId: 1, itemId: 1 }` для принадлежности, порядка и страниц; дополнительно `{ vkId: 1, kind: 1, reservedUntil: 1, itemId: 1 }` и `{ offerId: 1, vkId: 1 }` для доступного остатка и резерва |
| `notifications` | Уникальный `_id` вида `referral:VK_ID_новичка`; индекс `{ state: 1, nextAttemptAt: 1 }`, состояние отправки, lease и постоянный `random_id` |
| `promos` | Уникальный `_id` — регистрозависимое название; индекс `{ ownerId: 1, _id: 1 }` с бинарным сравнением для списка владельца. Награда, валюта, начальное количество и остаток |
| `promo_redemptions` | Уникальный `_id` из UTF-8 hex названия и VK ID; уникальный индекс `{ promoName: 1, vkId: 1 }`, без TTL |
| `counters` | Стандартный уникальный `_id`; счётчики `registrations` и `responses`, начальное значение 0 |
| `processed_messages` | Стандартный уникальный `_id`, составленный из ID сообщества, беседы и сообщения внутри беседы; сохранены отправитель и готовый ответ |

KC и евро хранятся целыми сотыми долями, биткоины — целыми сатоши, 100000000 на 1₿. Верхняя граница каждого денежного поля — `Number.MAX_SAFE_INTEGER` в минимальных единицах. Начисления проверяют верхние границы внутри фильтра атомарного `$inc`. Форматирование выполняется через BigInt без округления денежных значений через float; в MongoDB значения остаются безопасными целыми Number.

Регистрация, выдача ID, начисление бонуса, добавление кейса, увеличение личного ID предмета, выдача `random_id` и запись обработанного события выполняются в транзакциях `withTransaction` с `majority` и `snapshot`. Время бонусов и майнинга берётся из MongoDB через `$$NOW`, не из времени клиента VK или часов отдельного процесса. Все вызовы VK — вне транзакции.

Повторная доставка сообщения возвращает сохранённый результат. Одновременные разные сообщения не обходят кулдаун. При ошибке внутри транзакции не остаётся частично выданного бонуса, потерянного кейса или пропущенного последовательного ID регистрации. Ошибки уникальных индексов обрабатываются отдельно, с ограниченными повторами. Записи дедупликации не имеют TTL: удаление таких записей разрешило бы повторно применить старое событие после истечения кулдауна.

Для токена сообщества задан лимит 20 API-запросов в секунду с равномерной очередью, без burst. Режим `parallel_selected` объединяет ожидающие отправки `messages.send` в `execute`, до 25 за запрос; остальные методы выполняются отдельно. vk-io повторяет внешнюю ошибку лимита 6 с задержкой и делает до двух повторов транспортных ошибок. Для ошибки 6 отдельной отправки внутри `execute` обработчик делает до двух повторов с задержкой и тем же `random_id`. Используемые вызовы — чтение и отправка с сохранённым `random_id`, поэтому их повтор безопасен. Запрет отправки и недоступность беседы логируются без повторного начисления награды. В лог не передаются текст исключения VK, параметры запроса, токен и URI MongoDB.

При старте выполняется идемпотентная миграция существующих игроков: отсутствующая ферма получает базовые настройки, отсутствующие `referrals` и `stolenKC` получают 0. Имеющиеся балансы, ID, фермы и счётчики не сбрасываются. `referralUrl` сохраняется только после успешного сокращения ссылки. Новых обязательных переменных окружения и зависимостей нет. Коллекции и индексы промокодов создаются при инициализации, отсутствие `promoDraft` у старых игроков означает отсутствие черновика и не требует перезаписи игроков. Интерфейс хранилища `GameStore` дополнен операциями новых систем. Инициализация индексов и счётчиков также идемпотентна; повторный старт не сбрасывает данные. Нельзя удалять или сбрасывать счётчики отдельно от связанных коллекций.

## Администрирование

Команда `/dk` только в беседах удаляет текущую клавиатуру бота и отвечает ровно `Done.`. Доступ разрешён только VK ID `888801846`, список находится в `src/config/admin.ts`. Проверяются отправитель события и тип беседы; данные payload не дают прав. В личке и от других пользователей команда молча игнорируется. Команда не регистрирует администратора и не меняет игровые данные; дедупликация и сохранённый `random_id` используются как у остальных ответов.


### Управление балансом KC

Только VK ID `888801846` (из того же `adminIds`) может вызывать `!set` и `!add`, в личке и беседах. Остальные отправители молча игнорируются, в том числе при подделке payload. Права проверяются в обработчике и повторно в сервисе до чтения кеша события. Команды разбираются из текста, не из payload, и не попадают в текущий диалог промокодов.

- `!set 100` — установить себе 100 KC; `!add 100` — добавить себе 100 KC.
- В ответ на сообщение эти же команды изменяют баланс **автора исходного сообщения**, не отправителя команды, не автора пересланного сообщения.
- `!set @id123 100k` или `!add @id123 100k` — изменить баланс VK ID 123. Настоящие упоминания VK вида `[id123|Имя Фамилия]` тоже распознаются. Явная цель имеет приоритет над ответом.
- Сумма задаётся целым неотрицательным числом KC; суффикс `k`/`K` или `к`/`К` означает ×1000, `kk`/`кк` — ×1.000.000 (регистр не важен). Например, `100k` = 100.000 KC. `!set 10кк` устанавливает 10.000.000 KC, в том числе ответом на собственное сообщение. `!set 0` обнуляет баланс. Отрицательные, дробные, экспоненциальные и выходящие за безопасный диапазон значения отклоняются. Произведения вычисляются через BigInt.
- Меняется только поле `kc`, евро, BTC, бонусы, инвентарь и черновик промокода не затрагиваются. Игрок-цель должен быть зарегистрирован; новые аккаунты эти команды не создают, администратор при явной цели может быть незарегистрирован.
- При успехе ответ ровно `Done.`, без кнопок. В личке текущая клавиатура не заменяется; в беседе действует общее правило очистки старой клавиатуры. При неправильном синтаксисе, неизвестном игроке или переполнении — понятный отказ без изменения баланса.
- Изменение KC и сохранение ответа/`random_id` — одна транзакция. `!add` использует атомарный `$inc` с границами в фильтре, `!set` — `$set`; повторная доставка не добавляет деньги дважды и не применяет старую установку повторно. Дополнительных коллекций, индексов, миграций, зависимостей или ENV для этих команд нет.


## Предметы, кейсы, подарки и сделки

### Администрирование предметов

Доступ только у `888801846`, в личке и беседах, с повторной проверкой в сервисе до кеша события. Другие отправители молча игнорируются. Команды не регистрируют администратора или указанного игрока; цель должна уже существовать.

- `!itemlist` показывает `📖 ItemList:` и каталог: **1 — 💼 Кейс «Ждун»; 2 — 👬 Кейс «Реферальный»; 3 — 🤴 Крупьер**.
- `!giveitem <игрок> <каталожный ID> [количество]` выдаёт указанное количество от 1 до 1000 (без количества — одну штуку), `!takeitem <игрок> <каталожный ID>` забирает одну доступную штуку. Успех — ровно `Done.`. Резерв сделки не изымается; при отсутствии доступного предмета — отказ без изменений.
- Голое число цели ищется сначала по `accountId` бота (включая 0), затем по VK ID. `@id123`, `id123` и `[id123|Имя]` однозначно задают VK ID. Это устраняет неоднозначность маленьких чисел; явно указывайте `@id…`, когда нужен именно VK ID.
- Каталожный ID типа **не равен** личному ID экземпляра в инвентаре. Старые личные ID и имеющиеся кейсы сохранены. Одинаковые предметы, включая уже выданные, показываются одной строкой с полным количеством, например `(10 шт.)`, и одной кнопкой. Группировка выполняется в MongoDB до пагинации, без загрузки всех экземпляров в приложение. Поэкземплярное внутреннее хранение сохраняется для атомарного открытия, передачи и резервирования; пересоздавать или перенумеровывать существующие предметы не нужно. Новые экземпляры, в том числе подаренные и купленные, получают следующий личный ID получателя; удалённые ID повторно не используются.

### Открытие

В личном инвентаре кнопка `🆔 N` открывает карточку типа предмета через принадлежащий игроку экземпляр: название, доступное количество всего типа и список наград. Кнопки: использование, продажа, подарок, назад. «Использовать» предлагает `x1 | x5 | x10`, своё количество и назад. Доступный остаток не включает активные резервы продаж. Отсутствующий, чужой или уже использованный экземпляр не открывается.

С каждого кейса — ровно одна награда. У обоих кейсов одинаковая таблица, согласованная с владельцем:

| Награда | Вероятность |
| --- | --- |
| 1.500 KC | 30% |
| 2.500 KC | 30% |
| 15.000 KC | 30% |
| 1 евро | 5% |
| 2 евро | 3% |
| 5 евро | 2% |

`RW` было подтверждено как опечатка: это KC, отдельной валюты нет. Выбор через `crypto.randomInt(100)`, результат на время повторов транзакции сохраняется в обработке события, а после коммита — в сохранённом ответе. Израсходованные экземпляры, начисление KC/евро и ответ фиксируются одной транзакцией. Повтор события не расходует кейс и не начисляет награду заново. При нехватке экземпляров или переполнении кошелька ничего не применяется частично.

Свое количество вводится целым числом; `отмена`/`отменить` возвращают `Действие отменено.` и главное меню. Валидное количество готовит кнопку `Открыть`, без немедленного расходования кейсов. Кнопка связана с текущим черновиком и количеством; остаток проверяется снова при открытии. Диалог хранится в `players.itemDraft` и переживает перезапуск. За один вызов можно открыть, подарить или продать от 1 до **1000** экземпляров: это техническая граница размера транзакции, не ограничение общего инвентаря. Результат большого открытия группируется по шести видам наград с `xN`, чтобы сообщение всегда помещалось в лимит VK. В результате открытия пустая строка есть только после заголовка «Вот что выпало:», строки наград идут подряд. Подсказка получателя в подарке/продаже — две строки подряд, с VK-упоминанием `[id888801846|@kreox_owner]`.

### Подарки

Получатель задаётся числом ID бота (затем VK ID), `@id…`, настоящим упоминанием или коротким адресом `@kreox_owner` / `https://vk.com/kreox_owner`. Разрешение короткого адреса через `users.get` выполняется **вне** транзакции, найденный VK ID затем проверяется по зарегистрированным игрокам. Самому себе передавать нельзя.

После количества — инлайн-подтверждение. Только текущий черновик отправителя определяет тип, получателя и количество; поддельный payload не меняет их. Передача, выделение новых ID получателя, запись уведомления и ответ атомарны. Получатель получает уведомление вида `🎁 [id…|Имя] подарил вам … xN`. Если его личка закрыта, подарок остаётся переданным, уведомление отмечается неотправляемым без повторной передачи.

### Продажа

После получателя и количества вводится **цена всей партии**, не одной штуки. Поддерживаются целые KC, `к`/`k` = 1000 и `кк`/`kk` = 1000000: `10кк` = 10000000 KC. Нулевая цена допустима; отрицательные, дробные и переполняющие значения отклоняются. После инлайн-подтверждения сохраняются предложение и резерв конкретных экземпляров, а покупателю ставится в очередь сообщение с инлайн-кнопкой принятия. Деньги продавцу при отправке предложения не начисляются.

Резерв действует ровно 10 минут от времени MongoDB при подтверждении продавцом. Зарезервированные экземпляры нельзя открыть, подарить, повторно продать или изъять обычным `!takeitem`. Истечение не зависит от работающего таймера: доступность вычисляется по `reservedUntil <= now`, поэтому после перезапуска просроченные экземпляры сразу снова доступны. Истёкшее предложение нельзя принять даже если его кнопка сохранилась. Срок проверяется и при финальной записи успешной покупки по `$$NOW`.

Если все экземпляры типа зарезервированы активной сделкой, карточка и действия показывают «⚠️ У вас есть активная сделка на данный предмет!», затем пустую строку и «⏳ Подождите принятия сделки или аннулирование сделки.». Если свободная часть осталась, карточка показывает доступное количество, и открывать, дарить или продавать можно только эту часть. Например, из двух кейсов при резерве одного второй можно открыть; зарезервированный экземпляр не затрагивается. После истечения 10 минут резерв автоматически перестаёт ограничивать действия, без таймера и перезапуска.

Принять может только сохранённый покупатель. В одной транзакции проверяются срок, состояние предложения, принадлежность резерва, деньги покупателя и границы кошельков/ID; списывается общая цена, начисляется продавцу, экземпляры передаются и сделка помечается завершённой. Параллельные подтверждения завершают покупку только один раз. Ошибка или нехватка денег не расходует резерв и не делает частичного перевода; после пополнения можно принять предложение до истечения срока. Продавец получает отдельное уведомление об успешной покупке.

Уведомления подарков, предложений и продаж используют общую постоянную очередь с lease и стабильным `random_id`; для новых сообщений в записи хранится и спецификация клавиатуры, старые реферальные уведомления без этого поля продолжают отправляться без кнопок. «Предложение отправлено» означает сохранение в очереди, а не подтверждённое прочтение покупателем. Сам факт недоставки предложения не продлевает резерв.

Новых зависимостей и обязательных ENV нет. При запуске создаются коллекция предложений и индексы; старые экземпляры без `reservedUntil` считаются свободными, старые игроки без `itemDraft` не имеют активного диалога. Полная перезапись или перенумерация инвентаря не требуется. Работа с предметами — в личке; в беседах сохраняются прежние команды профиля/полного инвентаря без кнопок и доступны админские выдача/изъятие.


## Донат: ник, вор и крупье

Кнопка `🍩 Донат` открывает `💶 Донат:` и кнопки `👤 Ник | 🥷 Вор | 🤵‍♂️ Крупье`, ниже `↩️ Назад`. Все кнопки содержат проверяемый payload. Подтверждение зелёное, отмена красная; у покупки крупье подтверждение inline. Отмена возвращает `Действие отменено.` и главное меню. Новые текстовые исключения к payload-only: `купитькрупье` / `купить крупье` (личка и беседы), `крупье` и `вор` (только беседы). Слово `вор` в личке полностью игнорируется, без регистрации и ответа.

### Ник — 50 евро

Бот принимает 4–20 **видимых символов Unicode** (графем), включая эмодзи; пробелы по краям убираются. Для защиты упоминаний запрещены `[]|@*`, переносы строк, управляющие символы и маркеры направления текста. Небезопасный ник отклоняется, не подменяется другим. Уникальность ников не требуется. До зелёного подтверждения ник и евро не меняются. Подтверждение привязано к текущему черновику игрока и событию; повторный клик не списывает ещё 50 евро. Меняется существующее поле `name`, поэтому новые профили, рейтинги, карточки сделок и уведомления используют купленный ник, без повторного запроса имени в VK. Уже отправленные сообщения не переписываются.

### Вор — 200 евро на 30 дней

Покупка активирует подписку ровно на 30 × 24 часа; дата окончания показывается как `ДД.ММ.ГГГГ ЧЧ:ММ` в `Europe/Moscow`. Активная подписка показывается со сроком окончания и без повторной продажи/автопродления; купить следующую можно после истечения текущей.

`вор` в беседе выбирает равновероятно другого зарегистрированного участника **именно текущей беседы**, включая игроков с нулём KC. Полный список участников приходит из `messages.getConversationMembers` с пагинацией по 1000 (не только первые 20 участников по умолчанию) после проверки подписки и КД, **вне MongoDB-транзакции**; ID из пользовательского payload не используются. Боту нужен доступ к этому методу в беседе. При отказе VK кража не проводится; подмена выборкой всех игроков бота не выполняется. Выборка ограничена 10 000 ID, поиск использует индекс `_id`, в приложение загружается только один выбранный игрок.

Сумма равномерна от 0 до целой части баланса жертвы включительно, с шагом **1 KC**. Сотые KC остаются у жертвы. Например, из `123,45 KC` можно украсть от 0 до 123 KC. Баланс жертвы не становится отрицательным; KC не создаются, переводятся между кошельками. Увеличивается показатель `stolenKC` для существующего рейтинга воров. При переполнении кошелька или статистики операция отклоняется целиком.

После успешной попытки, **включая 0 KC**, устанавливается личный КД на час. Нет жертвы / ошибка / переполнение не запускают КД. В ожидании ответ: `[id…|ник], своровать можно будет через N мин. M сек.`. Параллельные сообщения не обходят КД. Подписка, КД, перевод, статистика, ответ и уведомление жертве фиксируются в БД; уведомление доставляет существующая надёжная очередь, недоступная личка не откатывает перевод.

### Крупье — 15 евро

В боте один общий крупье. `купитькрупье` / `купить крупье` покупают роль сразу; через донат сначала показывается описание и inline-подтверждение. Повторная покупка текущим крупье отклоняется без списания. После успешной смены действует **общий** КД 15 минут; новый обладатель `🤴 Крупьера` может обойти его, но также платит 15 евро. Каждая успешная смена снова выставляет общий срок от момента покупки.

В `dealer` хранится единственная запись `casino`: владелец, накопленные KC, время следующей смены. До первой покупки показывается «Государство» без VK-аккаунта. `крупье` в беседе показывает владельца и текущие накопления. При смене накопления переводятся **предыдущему** владельцу, новая копилка обнуляется и прежнему владельцу ставится уведомление с заработанной суммой. Списание евро, выплата, смена владельца, очередь и дедупликация выполняются в одной транзакции. Если выплата переполнит баланс прежнего владельца, покупка целиком отклоняется; евро не списываются и копилка не теряется.

Предмет `🤴 Крупьер` — каталог **ID 3**, выдаётся через `!giveitem <игрок> 3 [количество]`, можно дарить и продавать обычной системой. Не кейс: нельзя открыть ради награды, не расходуется при покупке роли. Снимает только КД, не цену и не запрет повторной покупки текущим владельцем. Право зависит от текущего владения предметом, не запоминается навсегда после передачи. Находящийся в резерве продажи предмет остаётся собственностью продавца до покупки и также даёт право обхода.

Крупье получает 1% от суммы проигравших ставок Краша и Дрима. Выигравшие ставки не дают ему дохода. Правила раундов и начисления приведены ниже.

### Хранение и проверки

Новые поля `players`: опциональные `donateDraft`, `thiefUntil`, `nextTheftAt`; отсутствие означает отсутствие диалога/подписки/КД. Имя хранится в прежнем `name`. При запуске запись `dealer/casino` создаётся через `$setOnInsert`, повторный запуск не сбрасывает владельца, копилку или КД. Необходим существующий replica set и транзакции. Новых зависимостей или обязательных ENV нет. Цены и интервалы — `src/config/donate.ts`; логика/тексты — `src/services/donate*.ts`; атомарные записи — `src/repositories/mongo-donate.ts`.

Добавлены модульные проверки подтверждений, длины и безопасности ников, дат МСК, границ подписки/КД, нулевой/максимальной кражи, членства беседы, гонок, дедупликации, откатов, смены и выплаты крупье, передачи предмета и реального обработчика vk-io с подменённым транспортом. `tests/integration/donate.test.ts` проверяет операции на настоящем MongoDB replica set при заданном `MONGODB_TEST_URI`; без него тест явно пропускается. Живое VK API и доступ к списку участников требуют отдельной проверки при развёртывании.

Официальная схема VK сверена через `VKCOM/vk-api-schema/messages/methods.json`: `messages.getConversationMembers` допускает group-токен, параметры `peer_id`, `group_id`, `offset`, `count` (максимум 1000, по умолчанию 20). Сигнатура сверена и с установленным vk-io 4.10.1. Это не заменяет проверку прав бота в живой беседе.


## Админские команды евро и BTC

Доступ только у существующего администратора `888801846`, в личке и беседах. `donut` управляет **существующим балансом евро 💶**, `bit` — кошельком BTC, не балансом майнинг-фермы:

- `!setdonut <VK ID> <сумма>` / `!setbit <VK ID> <сумма>` — установить баланс.
- `!adddonut <VK ID> <сумма>` / `!addbit <VK ID> <сумма>` — добавить.
- `!takedonut <VK ID> <сумма>` / `!takebit <VK ID> <сумма>` — забрать.

Можно использовать голый **VK ID**, `@id123`, `id123` или VK-упоминание. Это не внутренний ID аккаунта бота. Вместо ID можно ответить на сообщение игрока: `!adddonut 50`, `!takebit 0,500`. Явный ID приоритетнее ответа. Без ID и ответа применяется прежнее правило админских балансов: цель — сам администратор, если он зарегистрирован. Неизвестные игроки и администратор автоматически не регистрируются.

Суммы задаются в евро/BTC, не в сотых/сатоши. Евро допускают до 2 знаков после точки или запятой, BTC — до 3; `k`/`к` умножает на 1000. Примеры: `!setdonut 123 50,25`, `!addbit @id123 1.116`. Парсинг через BigInt, без денежных операций с float. Старые KC-команды `!set` / `!add` и их синтаксис не меняются.

Успех всех шести команд — строго `Done.` без клавиатуры. Отрицательные суммы, нехватка средств при `take`, переполнение, неправильный формат и неизвестный игрок отклоняются **без изменений**, с сообщением об ошибке, а не ложным `Done.`. При `take` сумма не урезается до остатка. Команды не трогают другие валюты, накопления крупье или активные диалоги. Баланс и сохранённый ответ меняются одной транзакцией; повторы события и параллельные списания не создают повторного дебета или отрицательного баланса.

Новых полей, зависимостей, ENV и миграций нет. Дополнены `handlers/admin-balance.ts`, `services/admin-balance.ts`, типы, атомарный метод репозитория и проверки модульного/интеграционного хранилищ.


## Город и банк

`🏙️ Город:` → `👑 Директор | 🏦 Банк | 🎰 Казино`, ниже `📕 Меню`. Директор открывает ежедневные выборы; правила ниже. Личный экран казино открывает меню бесед, ежедневного джекпота и монетки; Краш, Дрим и рулетка запускаются текстовыми командами в беседах. Кнопки, включая суммы депозитов и сроки, имеют payload. Одна лишь надпись кнопки действие не запускает. Город и банк предназначены для ЛС; в беседах доступны текстовые переводы без клавиатуры.

Банк содержит накопительный счёт, пенсию, перевод и депозиты. Черновик `bankDraft` хранится у игрока и переживает перезапуск. Навигация сбрасывает текущий банковский ввод; текстовая `отмена` / `отменить` отменяет диалог. Чужие или устаревшие подтверждения не применяются.

### Накопительный счёт

Подтверждённая ставка — **2% за полную неделю** (100 000 → 102 000), а не первоначальные 0,5%. Деньги отделены от кошелька: пополнение списывает KC с рук, снятие переводит со счёта на руки. Проценты капитализируются за полные периоды по 7 × 24 часа с округлением вниз до сотой KC на каждом периоде. Промежуточный просмотр не сбрасывает срок и не начисляет доход повторно. После любого успешного пополнения/снятия новый недельный срок начинается для всего оставшегося баланса. Неуспешная операция срок не меняет.

Начисление ленивое, по времени MongoDB, не зависит от постоянно работающего таймера. Счёт ограничен существующим безопасным целочисленным пределом; сверх него проценты не накапливаются. Переполненный кошелёк не позволяет снять средства: накопительный остаток при этом не теряется. KC принимаются целыми числами, с группировкой тысяч точкой, `к`/`кк`; сотые KC можно ввести через запятую (`1,02`), чтобы снимать дробный процентный доход. Все вычисления — целые минимальные единицы и BigInt.

### Переводы и комиссия

В ЛС: выбор KC/евро/BTC → получатель → сумма → перевод и уведомление получателю через постоянную очередь. Пользователь вводит **полную списываемую сумму**, получатель получает 95%. В ответе отправителю и уведомлении показывается полученная сумма: 100 KC → 95 KC. Комиссия не начисляется крупье или другому игроку. Полученная сумма округляется вниз до минимальной единицы валюты, остаток относится к комиссии. BTC в сообщениях, как и прежде, отображаются с тремя знаками, без потери точности внутреннего кошелька.

Текстовые команды в беседах и ЛС: `монеты`, `евро` / `донат`, `бит` / `биткоин`. Примеры: `монеты 100` ответом на сообщение, `монеты @id123 100`, `монеты 111 100`, `бит @id123 1,116`. Явный получатель приоритетнее ответа. Голое число цели — сначала **ID аккаунта бота**, затем VK ID, как у предметов; `@id123`, `id123` или VK-упоминание однозначно задают VK ID. Поддержан `@screen_name` через существующий резолвер VK, вне транзакции. Без явной цели или ответа перевод не выполняется. Перевод себе, неизвестному игроку, сверх баланса или с переполнением получателя отклоняется без списания. KC допускают сотые через запятую, евро — до двух, BTC — до трёх знаков; суффиксы `к`/`кк` масштабируют введённую сумму.

### Регистрация и пенсия

При запуске **отсутствующий** `registeredAt` старых игроков устанавливается в серверное `$$NOW` MongoDB. Это согласованная дата начала отсчёта после внедрения функции, а не выдуманная историческая регистрация. Повторный запуск дату не меняет. Новые игроки получают дату при регистрации в той же транзакции.

В профиле/меню ЛС перед ID добавлена строка `🤖 В боте N дней. | ДД.ММ.ГГ ЧЧ:ММ` по Москве. Между полями нет пустых строк. В беседах сохранён прежний семистрочный профиль. Возраст — полные прошедшие сутки с регистрации, без зависимости от локальной даты устройства.

До 30 полных дней пенсии нет. В возрасте **30–60 полных дней включительно** выбирается равновероятно одна сумма: 500 / 700 / 900 / 1000 / 1200 / 1500 / 1800 / 2500 / 5000 KC. При **более 60 полных днях**: 5000 / 7000 / 10000 / 12000 / 15000 / 20000 / 25000 KC. После успешной выплаты — ровно 24 часа КД, не календарная полночь. Неуспешная выплата и переполнение баланса не расходуют КД. Результат случайного выбора сохраняется на повторах транзакции; повторная доставка события не выдаёт новую пенсию.

### Депозиты

Максимум **5 активных** депозитов, сумма одного — не более **10 000 000 KC**. Перед созданием сумма проверяется и при нажатии срока повторно проверяется кошелёк. До выбора срока списаний нет. Кнопки 5/10/20/50/100% используют текущий баланс, округлённый вниз до целого KC; сумма в payload не даёт обходить максимум или наличие средств. При изменении кошелька используется повторная серверная проверка. Личные ID депозитов идут с 1, монотонно растут, не повторяются после закрытия. Создание, списание и обработанное событие атомарны; параллельные создания не обходят лимит пяти.

Ставки: **3 дня — 2%, 10 дней — 4%**. В примерах RW заменён на KC, новой валюты нет. Доход растёт линейно по прошедшим миллисекундам до конца срока, без капитализации внутри депозита; дробные минимальные единицы округляются вниз. Карточка показывает текущую сумму и даты по Москве в виде `25 октября 2026 00:02:09`.

Досрочное снятие требует inline-подтверждения, возвращает **90% текущей суммы вместе с накопленным доходом**, округлённых вниз до сотой KC. Между показом и подтверждением доход может увеличиться — выплата рассчитывается на момент подтверждения, не становится меньше показанной. Если срок к моменту подтверждения уже вышел, применяется обычное завершение с полным доходом, **без 10% штрафа**. Старые кнопки, чужой ID или повторное подтверждение не списывают/не возвращают средства повторно.

По окончании вклад **автоматически** возвращается в кошелёк. Уведомление: `🏧 Ваш депозит ID: N был окончен.`, пустая строка, затем `Баланс до`, `Баланс после`, `Процент`, `💰 Вы заработали`. Здесь баланс до/после — первоначальный вклад и его итоговая сумма, чтобы заработок равнялся именно процентному доходу, а не всей возвращённой сумме.

Обработчик запускается сразу при старте и затем каждые 5 секунд, по 20 записей за проход. Очередь выбирает просроченные записи по индексу. Состояние депозита, деньги и запись уведомления меняются одной транзакцией; параллельные экземпляры процесса не дублируют выплату. При остановленном боте просроченные депозиты остаются в БД и выплачиваются после запуска. Закрытые ЛС не отменяют выплату. Если кошелёк переполнен, депозит остаётся активным, выплата повторяется через минуту; другие депозиты не блокируются и деньги не обрезаются. Ограничение пяти сохраняется до фактического закрытия.

### Данные, файлы и проверка

Новые опциональные поля игрока: `registeredAt`, `savingsBalance`, `savingsSince`, `nextPensionAt`, `nextDepositId`, `bankDraft`. Отсутствующий накопительный счёт равен нулю; отсутствие КД означает отсутствие предыдущей выплаты. Коллекция `deposits` хранит владельца, личный ID, сумму, срок, даты, статус и время следующей попытки выплаты. Создаются индексы `(vkId, state, depositId)`, уникальный `(vkId, depositId)`, очередь `(state, nextAttemptAt, _id)`. Запуск не сбрасывает имеющиеся суммы/счётчики/сроки.

Настройки — `config/bank.ts`, типы — `types/bank.ts`, логика и отдельные тексты — `services/bank*.ts`, атомарные записи — `repositories/mongo-bank.ts`, парсер/таймер — `handlers/bank*.ts`. Дополнены клавиатуры, профиль, диспетчер и graceful shutdown. Новых зависимостей и обязательных ENV нет. VK-сетевые вызовы и доставка уведомлений остаются вне транзакций; изменения денег, подтверждения и дедупликация — внутри.

`tests/bank.test.ts` проверяет проценты, сброс срока при движении, комиссию, валюты и адресатов, даты, пенсию, подтверждения, лимиты, повторы, гонки, раннее/обычное снятие, переполнение и откаты. Есть реальный обработчик vk-io с подменой транспорта. `tests/integration/bank.test.ts` проверяет миграцию, деньги и гонки на настоящем replica set при заданном `MONGODB_TEST_URI`; без URI явно пропускается. Подменённое хранилище не является доказательством работы гонок на настоящей MongoDB; живой VK также требует проверки при развёртывании.


## Топы в беседах

Все команды нечувствительны к регистру и возвращают существующий глобальный топ-20 с местом вызывающего игрока, без кнопок: `топ` — KC; `топ бит` / `топ биткоин` — BTC; `топ вор` / `топ воров` — украденные KC; `топ реп` — репутация; `топ донат` / `топ евро` — евро; `топ реф` / `топ рефералы` — рефералы; `топ майнинг` — скорость майнинга. В ЛС эти текстовые алиасы не включены, чтобы не перехватывать свободный ввод диалогов.

## Директор и выборы

Директор один на весь бот. До первой победы и в день без участников — **Государство**, не аккаунт игрока. Крупье без владельца также показывается как Государство. Это независимые должности, один человек может владеть обеими.

Кнопка директора в городе показывает текущего владельца, заработок, время выборов, общий пул и личную ставку с шансом. `Сделать ставку` → ввод → зелёное подтверждение / красный возврат. Кнопки имеют payload. Каждый подтверждённый взнос не менее **1000 KC** добавляется к личной ставке и сразу списывается с кошелька. До подтверждения списаний нет. Повторные/чужие/старые подтверждения не тратят деньги. Ставка относится только к текущему выборному дню; подтверждение после его закрытия не попадает в следующий день.

В **00:00 МСК** серверный обработчик замораживает пул. Шанс каждого равен его общей ставке / общему пулу. Используется криптографический равномерный целочисленный билет по всему пулу, без погрешности Number или ограничений `randomInt` на крупные суммы. Проценты в интерфейсе округлены вниз до двух знаков и не участвуют в выборе. Победитель расходует всю свою ставку, проигравшим возвращаются **50% личной общей ставки**, округлённых вниз до сотой KC. Пул следующего дня начинается с нуля, старые ставки не переносятся. Без участников новым директором становится Государство.

Директор получает **1% от всех принятых казино-ставок**, а не только проигравших. Доход начисляется при приёме каждой ставки текущему директору, на полночь накопления становятся отдельной долговечной выплатой старому директору. Отменённые/непринятые строки дохода не дают. Государство не получает реальный кошелёк или выплаты.

Итоги выборов ставятся в постоянную очередь во все известные активные беседы; проигравшим — личный возврат и уведомление, победителю — личное поздравление. `директор` в беседе показывает текущего владельца и заработок, без кнопок. При недоставке уведомления экономические результаты не отменяются и не повторяются.

Список бесед сохраняется из входящих событий, включая служебные события, и синхронизируется перед запуском обработчика выборов / затем раз в минуту через пагинированный `messages.getConversations` (`count: 200`, `filter: all`, `group_id`). Беседы с явным статусом выхода/исключения или запретом писать исключаются; личные диалоги не участвуют. Удаление сообщества из беседы учитывается по служебному событию. Метод поддерживает токен сообщества по официальной схеме VK, но доступ конкретного рабочего токена и фактическое покрытие списка проверяются на живом VK. Ошибки синхронизации имеют отдельный безопасный лог `chat_registry`, бот продолжает работу с сохранённым списком.

## Краш и Дрим

Только беседы. В каждой беседе отдельный раунд каждой игры. Команды: `краш <коэффициент> <ставка>`, `дрим <сектор> <ставка>`, `лог краш`, `лог дрим`. Минимальная ставка обеих игр — **1000 KC**, максимум **10 принятых ставок на игрока за раунд каждой игры**. Принимаются `к`/`кк`, точка как разделитель тысяч KC и сотые через запятую. RW нигде не добавляется.

Вместо числовой суммы обе игры принимают `пол` — половину текущего кошелька (округление вниз до сотой KC), `все` / `всё` / `вб` — весь текущий кошелёк, без учёта регистра. В многострочном сообщении баланс перечитывается внутри той же транзакции для каждой такой строки: после принятой ставки следующая использует оставшиеся деньги. Отклонённые строки баланс не меняют. Минимум 1000 KC и проверки возможной выплаты остаются в силе. Например: `краш 1.7 пол`, `дрим 20 вб`.

Несколько команд можно прислать с новых строк, **включая смесь игр**:

```text
краш 1.7 100к
дрим 20 100к
краш 1.1 1к
```

Строки проверяются по порядку. На отклонённую строку не списываются деньги; уже принятые строки видны в том же ответе. Все принятые строки, версии раундов, доход директора и готовый ответ события фиксируются одной транзакцией. Повтор события после перезапуска не ставит повторно. Один запрос не обходит лимиты, даже если содержит много строк или выполняется одновременно с другим сообщением.

Первая ставка создаёт раунд и запускает **10 секунд** приёма. Каждая последующая принятая ставка, включая того же игрока и строки того же сообщения, добавляет **0,5 секунды** к сроку **своей** игры. Ошибки и отклонённые ставки не продлевают время. После дедлайна новые ставки не принимаются, даже если обработчик задержался. Конкуренция с закрытием защищена версией записи и проверкой `$$NOW` в атомарном фильтре; частично списанного сообщения не остаётся.

Закрытие создаёт уведомление о завершении приёма. После подтверждения его доставки запускаются **5 секунд** до итогов. Пока результаты не отправлены целиком, следующий раунд не открывается. Это сохраняется после остановки процесса. Реальная доставка зависит от очереди и доступности VK: точное сетевое время и одновременная доставка всем беседам не гарантируются. Неисправимые ошибки отправки фиксируются как `failed`, а не блокируют беседу навсегда.

### Коэффициент Краша

Разрешены коэффициенты **больше 1 и не больше 5000**, до двух знаков после точки/запятой; в ответах используется точка. После дополнительного согласования возврат Краша установлен в **97%, не 99%**: 99% вместе с доходами обеих должностей давали положительное суммарное ожидание игрокам.

Формула в сотых: `clamp(floor(97 × 1_000_000_000 / U), 100, 500_000)`, где U — равномерное целое 1…1 000 000 000. Шанс достижения x2 — 48,5%, x10 — 9,7%. Возможен мгновенный x1.00; максимум результата x5000. Ставка выигрывает при результате **не меньше** выбранного коэффициента. Выплата — ставка × выбранный коэффициент, включая первоначальную ставку, с округлением вниз до сотой KC. Более высокий фактический краш не увеличивает выбранную выплату.

### Сектора и бонус Дрима

Сектора `1 / 2 / 5 / 10 / 20 / 40`, базовые выплаты `×2 / ×3 / ×6 / ×11 / ×21 / ×41`. Согласованные веса выбора сектора: **23 / 15 / 7 / 4 / 2 / 1**, сумма 52. Независимый второй выбор: **×7 — 0,1%, ×2 — 1%, иначе без бонуса**. Бонус может выпасть с абсолютно любым сектором; бонусы не складываются и не запускают дополнительный раунд. Например, сектор 2 + ×7 даёт ставке на сектор 2 выплату ×21. Другие секторы в таком раунде проигрывают.

### Выплаты, сообщения и журнал

Крупье получает **1% только от проигравших ставок**, округлённый вниз до сотой KC на ставку. Получатель фиксируется при переходе к расчёту результатов. Если во время расчёта роль уже сменена, ещё не обработанный доход прежнего владельца сохраняется как его личная выплата, а не уходит новому крупье. Это не меняет существующую покупку роли и выплату уже накопленной копилки при смене.

Победные выплаты, возвраты выборов, доход прошлого директора и доход крупье имеют постоянные уникальные записи. При заполненном кошельке/копилке они остаются ожидающими, с повтором через минуту, без обрезания и повторного начисления. Пользователь получает сообщение о сохранённой выплате; уведомление «Возвращено» отправляется только после фактического возврата. Недоступность одного кошелька не блокирует итоги и другие выплаты.

Возможная выплата каждой ставки и суммарные показатели раунда ограничены существующим безопасным целочисленным пределом. Для Дрима проверяется худший бонус ×7. Ставка, которая не помещается в этот диапазон, отклоняется **до списания**, а не превращается в невыплачиваемый выигрыш. Это техническая защита Number, не новый игровой лимит обычных ставок.

В итогах сохраняются все выигравшие ставки и их призы, плюс общая сумма проигравших ставок; при отсутствии победителей — отдельный текст «Все ставки проиграли». VK ограничивает одно сообщение 4096 символами: длинный результат разбивается на последовательные части **без ограничения числа выигравших и без обрезания**. Части, их `random_id` и порядок отправки сохранены в БД. Длинные ответы на многострочный ввод также передаются через постоянную очередь частями; обычный короткий ответ — одно сообщение. Журнал каждой игры/беседы содержит последние 20 результатов, от старого к новому, новый всегда внизу; бонус Дрима отображается вместе с сектором и итоговой выплатой.

### Хранение и проверка

Коллекция `casino_records` хранит типизированные записи раундов, ставок, выплат, страниц итогов, директора, выборов, личных ставок, доставки ответов и реестра бесед. `_id` уникален, `version` защищает изменения от гонок. Индексы покрывают очереди по типу/статусу/сроку, ставки раунда/игрока, участников выборов и активные беседы. Выбор участника читает не больше существующего предела аккаунтов; расчёт/возвраты выполняются небольшими отдельными транзакциями. Отдельное опциональное поле `players.directorDraft` хранит ввод и подтверждение, отсутствие означает отсутствие диалога. Инициализация индексов идемпотентна, старые данные и суммы не сбрасываются.

Обработчик запускается сразу и затем каждые 250 мс, не более 40 шагов за проход, без локальных экономических блокировок. Решение раунда сохраняется при создании, выбор победителя выборов — атомарно на закрытии; при восстановлении не перебрасываются уже сохранённые результаты. Просроченные выборы и раунды продолжаются после перезапуска. После коммита новых сообщений казино обработчик будит общую очередь уведомлений, не ожидая её обычного двухсекундного интервала. Нет сетевых вызовов VK внутри денежных транзакций. Новых зависимостей и обязательных ENV нет; replica set остаётся обязательным.

Файлы: `config/casino.ts`, `types/casino.ts`, `services/casino*.ts`, `services/director.ts`, `repositories/mongo-casino.ts`, `handlers/casino*.ts`, `handlers/chat-registry.ts`; дополнены команды, клавиатуры, диспетчер, запуск/остановка, типы и README. Проверки: модульные математические/экономические сценарии, реальный обработчик vk-io с подменой транспорта, пагинация бесед и необязательный `tests/integration/casino.test.ts` для настоящего MongoDB replica set. Без `MONGODB_TEST_URI` последний явно пропускается; модульные гонки не заменяют проверку настоящей MongoDB или живого VK.

## Европейская рулетка

Только беседы: `<число или диапазон> <ставка>` (например, `ч1 10к`, `красное 1к`, `0 1000`), `лог рулетка`. Полная запись `рулетка <число или диапазон> <ставка>` тоже работает. Валюта — KC. Рулетка использует те же лимиты, таймеры, относительные ставки (`пол`, `все` / `всё` / `вб`), многострочные команды, доходы должностей и долговечные выплаты, что Краш и Дрим. В одном сообщении разрешено смешивать все три игры, например:

```text
рулетка красное 1к
краш 1.7 пол
дрим 2 1к
рулетка 0 вб
```

Все 37 чисел 0–36 равновероятны. Множители означают полную выплату, включая ставку:

| Ставка | Числа | Выплата |
| --- | --- | --- |
| Отдельное число | 0–36 | ×36 |
| `п1` / `п2` | 1–18 / 19–36 | ×2 |
| `д1` / `д2` / `д3` | 1–12 / 13–24 / 25–36 | ×3 |
| `ч1` / `ч2` / `ч3` / `ч4` | 1–9 / 10–18 / 19–27 / 28–36 | ×4 |
| `четное` / `нечетное` | Чётные / нечётные 1–36 | ×2 |
| `красное` / `черное` | Стандартные европейские цвета | ×2 |
| `большие` / `малые` | 19–36 / 1–18 | ×2 |

Варианты с `ё` и разный регистр принимаются. Зелёный 0 выигрывает только ставку на число 0: все диапазоны, цвета и чётность проигрывают. Журнал показывает последние 20 завершённых результатов от старого к новому с цветом числа. Для `ч3` используется диапазон 19–27, исправляющий опечатку 19–17.

### Фотографии итогов

Все 37 исходных HTTPS-ссылок находятся в `src/config/roulette.ts`, индекс соответствует результату. К первой странице итогов прикрепляется **настоящее фото VK**, а не URL в тексте или предпросмотр ссылки. Фотография скачивается с ограничением 30 секунд и 10 МиБ, без редиректов, только по настроенному URL; проверяется сигнатура JPEG. Затем `vk.upload.messagePhoto` загружает Buffer через `photos.getMessagesUploadServer` / `photos.saveMessagesPhoto`, полученный `photo<owner>_<id>[_access_key]` передаётся в `messages.send.attachment`. Загрузка имеет отдельный таймаут 30 секунд. Сетевые вызовы выполняются только вне денежных транзакций.

Отдельный фоновый обработчик начинает подготовку фото уже во время приёма ставок: каждые 2 секунды читает активные раунды рулетки ограниченными страницами из БД, не более двух одновременных подготовок. Исход уже сохранён при создании раунда; подготовка его не меняет и не публикует до итогов. После перезапуска активные раунды обнаруживаются снова. Чтение заканчивается до сетевых вызовов; обработчик не задерживает денежный расчёт или объявление закрытия ставок. Если к итогам загрузка ещё идёт, отправка в том же процессе ждёт уже запущенную операцию, а не начинает вторую. В разных процессах возможна повторная подготовка одного фото, но не повторные выплаты. Готовое вложение берётся из постоянного кэша. При перегрузке/медленной сети фото всё ещё может не успеть к итогам.

Кэш `message_photos` хранит вложение по ключу сообщества, беседы и исходного URL. Он переживает перезапуск; уникальный индекс `_id` создаётся MongoDB автоматически. В очереди уведомлений опциональное поле `roulettePhoto` хранит результат, включая 0; сохранённый `random_id` используется повторно при сетевом повторе отправки. Ошибка получения/загрузки фото не отменяет выплату и не блокирует раунд: отправляются текстовые итоги. Ошибка записи кэша не мешает отправить уже загруженное фото. При ошибке фото лог `roulette_photo_upload` содержит этап `cache_read`, `download` или `vk_upload`, время этого этапа в `elapsedMs` и лимит в `timeoutMs`. Это различает сбой CDN и сбой загрузки в VK; `AbortError` сам по себе не указывает этап. Увеличение таймаута с 10 до 30 секунд не гарантирует доступность CDN/VK. Логи не содержат токенов, исходных URL или сообщений сетевых ошибок.

Документация: [руководство загрузки vk-io](https://github.com/negezor/vk-io/blob/master/docs/ru/guide/upload.md), [официальная схема методов photos VK](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json). Схема разрешает оба метода загрузки с токеном сообщества. Собственная ограниченная загрузка в Buffer нужна потому, что в установленной vk-io 4.10.1 таймаут загрузки не ограничивает скачивание URL-источника.

Файлы: `config/roulette.ts`, `services/roulette-rules.ts`, `services/roulette-texts.ts`, `handlers/roulette-photos.ts`, `repositories/mongo-message-photos.ts`, `types/message-photos.ts`; расширены общие обработчики/сервисы казино, очередь уведомлений, транспорт и запуск. Новых зависимостей, обязательных ENV и миграции балансов нет; старые записи не меняются. Индекс `{ kind, mode, stage, _id }` для фоновой подготовки создаётся идемпотентно при запуске. Модульные тесты покрывают все цели/исходы, выплаты, повтор событий, лимиты, смешанные команды, роль директора/крупье, страницы итогов, нулевой результат, загрузку, кэш и текстовый fallback. Подменённые HTTP/VK-вызовы не подтверждают доступность исходного CDN, права рабочего токена или фактическую доставку вложения в живом VK.

## Админская рассылка

Только администратор `888801846`, в личке или беседе:

```text
/mailing Текст новости для пользователей
```

Текст может быть многострочным, до 4096 символов без префикса команды. Звёздочки вокруг текста не нужны. Сообщение передаётся без дополнительного заголовка и без клавиатуры. Пустой/слишком длинный текст получает подсказку; чужая команда молча игнорируется. Ответ «Рассылка поставлена в очередь» подтверждает создание задания, **не доставку всем получателям**. Повтор того же входящего события возвращает прежний ответ, а новое сообщение с той же командой создаёт отдельную рассылку.

Получатели — **все, кто писал боту в личные сообщения**, не только буквально отправившие «Начать». Игроки, пользовавшиеся исключительно беседами, не включаются. При первом обновлении список восстанавливается из сохранённых `processed_messages`: личный `peer_id` в ID события должен совпадать с его отправителем. История VK дополнительно не скачивается; удалённые старые события восстановить нельзя. Новые личные обращения учитываются автоматически, независимо от прежней регистрации в беседе. Пользователи, впервые написавшие после создания задания, не добавляются в уже идущую рассылку.

Коллекции `mailing_recipients`, `mailing_campaigns`, `mailing_migrations` создаются автоматически. История читается страницами по 100 записей через индекс `_id`, миграция идемпотентна и сохраняет контрольную точку после записи получателей. Повторные события и перезапуск не дублируют получателей. Денежные балансы и инвентарь не меняются; дополнительных зависимостей или ENV нет.

Фоновый обработчик раз в секунду атомарно добавляет в существующую очередь не более 20 личных сообщений и продвигает курсор задания. Сообщения имеют постоянные уникальные ID и `random_id`; очередь продолжает незавершённую доставку после перезапуска. Сетевых вызовов внутри транзакций нет. Индексы заданий и приоритета очереди создаются идемпотентно. Рассылка имеет меньший приоритет, чем игровые и прочие уведомления. Общие ограничения VK и обработка временных ошибок сохраняются; закрытые ЛС фиксируются как недоставка конкретному человеку и не блокируют остальных. VK всё равно может ограничить доставку — гарантии получения каждым человеком нет.

Основные файлы: `config/mailing.ts`, `types/mailing.ts`, `handlers/mailing.ts`, `handlers/mailing-worker.ts`, `services/mailing.ts`, `services/mailing-rules.ts`, `services/mailing-texts.ts`, `repositories/mongo-mailing-migration.ts`; расширены основной сервис, MongoDB-хранилище, диспетчер и запуск. Тесты покрывают парсер, права, список личных получателей, повтор событий, страницы, откат, продолжение задания и закрытые ЛС. Реальные MongoDB-транзакции/миграция проверяются отдельным опциональным `tests/integration/mailing.test.ts`; подменённый VK не подтверждает живую массовую доставку.

## Казино в личных сообщениях: джекпот и монетка

Кнопка «Казино» в городе теперь открывает меню с текущим крупье и его существующим заработком KC, без новой роли или валюты. Кнопки: `💬 Беседы`, `🎰 Джекпот`, `🪙 Монетка`. В «Беседах» — настоящая кнопка VK `open_link` «Чат #1» на настроенную ссылку приглашения и «Назад» в казино. Все текстовые кнопки работают по payload; подпись без payload не выполняет действие. Новые игры доступны только в ЛС, прежние Краш/Дрим/рулетка в беседах не меняются.

### Ежедневный джекпот

Участие **бесплатное**, один раз на зарегистрированный VK ID за раунд. Начальная казна создаётся системой: равномерное целое **1.000–1.000.000 KC**, обе границы включены. Каждое новое участие независимо имеет 50% шанса не изменить казну и 50% — добавить равномерные целые **5.000–100.000 KC**. Это согласованный новый источник KC, не списание с кошелька и не доход директора/крупье. Повтор регистрации или доставки одного события не увеличивает казну и число участников.

Розыгрыш ежедневно в **19:30 МСК (UTC+3)**: один равновероятный участник получает всю казну. Победитель, долг по выплате, объявление и переход к новому дню фиксируются атомарно. Участникам, кроме победителя, отправляется личное объявление с его упоминанием и суммой; победителю — отдельное поздравление после фактического начисления. Очередь хранит все сообщения, объявления разбираются страницами по 20 участников. Массовые объявления проигравшим имеют низкий приоритет, как рассылка, и не вытесняют игровые уведомления. Закрытые ЛС не отменяют результат. При переполненном кошельке выигрыш остаётся точной долговечной выплатой и повторяется через минуту, без обрезания.

После розыгрыша создаётся новая случайная начальная казна, список участников обнуляется для нового раунда. При отсутствии участников никто не получает деньги, старая казна **не переносится**. После простоя незавершённый старый раунд разыгрывается один раз; новый назначается на ближайшие будущие 19:30, без серии фиктивных пустых розыгрышей. Дедлайн проверяется по времени MongoDB, запись участия защищена версией и атомарной проверкой `$$NOW`; после 19:30 вступить в старый розыгрыш нельзя. На инициализации обработчик создаёт первый раунд даже без посетителей меню.

### Монетка

Минимум **1.000 KC**, ставки в KC, поддерживаются `к`/`кк`, `пол`, `все`/`всё`/`вб`. Сумма резервируется один раз при вводе, следующие броски повторно кошелёк не списывают. До первого броска можно изменить ставку: атомарно меняется только разница между старой и новой суммой. Относительная ставка при замене считается от доступного кошелька вместе с прежним резервом. После первого броска менять сумму нельзя.

Независимые равные шансы 💎/🟢 на каждом из семи ходов. Слегка сниженные полные множители: **×1,8 / ×3,6 / ×7,2 / ×14,4 / ×28,8 / ×57,6 / ×115,2**. Вероятность семи успехов подряд — 1/128. Базовый математический возврат при снятии на любом из этих ходов — 90%; первоначальная таблица ×1,9… заменена по дополнительному запросу. Выплаты вычисляются BigInt с округлением вниз до сотой KC. Перед резервированием проверяется возможная выплата последнего хода на безопасный предел Number.

До ставки боковые кнопки и снятие показывают «Сначала введите ставку»; после ставки, но до броска, снятие показывает «Вы еще не подкидывали монетку». После успеха доступны следующий бросок или снятие полной выплаты. На седьмом успехе полная выплата начисляется автоматически, а строка «чистый выигрыш» показывает **выплата − первоначальная ставка**. Ошибка выбора теряет исходную ставку и неснятый возможный выигрыш, без дополнительного списания. Переполнение кошелька сохраняет полную выплату в существующей очереди долгов.

При зарезервированной ставке и во время серии «Назад»/«Меню» и другая обычная навигация блокируются текстом `⚠️ У вас идёт активная игра в режиме «Монетка»!`. Игра сохраняется после перезапуска, выход из процесса ничего не списывает и не возвращает. Кнопки содержат идентификатор сессии и номер хода; два нажатия одной старой кнопки не совершают два броска или снятия. Новая ставка создаёт новую сессию. Само решение, деньги и сохранённый ответ события находятся в одной транзакции.

Директор получает существующий 1% от окончательной ставки **один раз при первом броске**, не при каждом редактировании резерва: иначе бесплатной сменой суммы можно было бы накручивать доход должности. Крупье получает существующий 1% только от проигранной первоначальной ставки, не от промежуточного неснятого выигрыша. Согласованные правила должностей, безопасные границы и долговечные выплаты сохраняются; сочетание обеих должностей не делает монетку прибыльной по математическому ожиданию.

### Хранение и проверки

Новые типы записей `coin`, `jackpot`, `jackpot_entry`, `jackpot_draw` используют существующую коллекцию `casino_records`, уникальные `_id` и оптимистические версии. Опциональный `players.coinOpen` определяет ввод суммы в ЛС. Добавлен идемпотентный индекс `{ kind, roundId, _id }` для страниц участников. Старые записи/балансы не сбрасываются, обязательных ENV и зависимостей нет. Фоновый обработчик джекпота запускается сразу, затем раз в секунду, не перекрывает собственные проходы и останавливается штатно. VK/сетевая загрузка отсутствуют в денежных транзакциях. Расчёт старого раунда восстанавливается после простоя; точная секунда доставки зависит от доступности MongoDB и VK.

Основные файлы: `config/private-casino.ts`, `types/private-casino.ts`, `handlers/private-casino.ts`, `handlers/jackpot-worker.ts`, `services/private-casino*.ts`, `services/coin*.ts`, `services/jackpot.ts`; обновлены кнопки, диспетчер, сервис, MongoDB-хранилище и запуск. Модульные тесты покрывают ставки, семь ходов, повторные нажатия, снятие, доходы должностей, переполнение, откат, ежедневный дедлайн, регистрацию, выбор победителя и все объявления. Отдельный опциональный `tests/integration/private-casino.test.ts` проверяет гонки и транзакции на настоящем replica set. Подменённый VK и модульные тесты не подтверждают живую доставку или устранение ранее наблюдавшихся сетевых тайм-аутов MongoDB.


## Компактная сборка для хостинга

Исходники остаются модульными для безопасных правок, но весь собственный код приложения собирается в **один `bot.mjs`**. Команда в исходном репозитории на Node.js 24:

```sh
npm ci
npm run build:hosting
```

Результат: папка `hosting/` и архив `kreox-hosting.tar.gz`, внутри **шесть файлов**: `bot.mjs`, `package.json`, `package-lock.json`, `.env.example`, `.nvmrc`, `README.md`. Сборка проверяет типы, использует закреплённый dev-инструмент **esbuild 0.28.2** и создаёт отдельный производственный lockfile. Для архива нужен `tar`. Настоящий `.env`, тесты, исходники и `node_modules` не упаковываются, файлы сборки в Git не добавляются.

После распаковки на хостинге с Node.js 24 выполните `npm ci --omit=dev`, настройте прежние ENV/базу и запускайте `npm start`. В сгенерированном пакете **нет `prestart` и компилятора**: исходники, TypeScript и esbuild на сервере не нужны. Сторонние библиотеки mongodb/vk-io и их зависимости npm ставит отдельно в `node_modules`; это не автономный исполняемый файл без зависимостей. Для Long Poll нужен постоянный фоновый процесс, не статический/PHP-хостинг или короткоживущая функция. Подробная инструкция — `HOSTING.md` (копируется в архив как `README.md`). При переезде остановите старый процесс и сохраните прежние `MONGODB_URI`/`MONGODB_DB`, чтобы не создать пустую игру.

В диагностике фото код VK **100** означает отказ из-за параметров, а не превышение тайм-аута. Дополнительно логируются размер загружаемого файла `photoBytes`, только разрешённое имя метода (`photos.getMessagesUploadServer` / `photos.saveMessagesPhoto`, либо `unknown`, если VK не указал его) и безопасная подсказка `parameterHint` из набора `peer_id`, `photo`, `server`, `hash`. Полные сообщения ошибок, параметры, адрес upload-сервера, хеши и токены не печатаются. Эта диагностика **не подтверждает исправление причины** кода 100; нужно посмотреть новый лог. Сборка для хостинга также не устраняет сетевые ошибки MongoDB/VK.
