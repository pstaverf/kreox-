# Kreox: запуск на хостинге

Требуется хостинг с **Node.js 24**, npm, постоянным фоновым процессом и исходящим доступом к VK, MongoDB Atlas и `cdn.kleymorf.xyz`. Бот работает через Long Poll и не открывает HTTP-порт: выбирайте фоновый процесс/worker, а не веб-сервис с обязательным HTTP health check. Обычный статический хостинг/PHP или функция с коротким временем жизни не подходят.

## Что загружать

В корне репозитория уже находятся файлы для запуска. Либо распакуйте `archives/kreox-hosting.tar.gz`: внутри ровно шесть файлов. Папка `backup/` на хостинг не нужна.

- `bot.mjs` — вся логика приложения в одном собранном файле.
- `package.json` — зависимости и команда запуска, без сборки перед стартом.
- `package-lock.json` — зафиксированные производственные зависимости.
- `.env.example` — пустой шаблон настроек, не рабочие секреты.
- `.nvmrc` — версия Node.js.
- `README.md` — эта инструкция.

Исходники `backup/src`, тесты `backup/tests`, TypeScript и esbuild на хостинг загружать не нужно. Библиотеки mongodb/vk-io и их зависимости **не встроены** в `bot.mjs`: npm установит их в `node_modules`. Это не один полностью автономный файл без зависимостей.

## Первый запуск

В корне распакованной папки:

```sh
node --version
npm ci --omit=dev
cp .env.example .env
```

Перед `npm start` заполните `.env` **на хостинге** либо задайте переменные в его панели: `VK_TOKEN`, `VK_GROUP_ID`, `MONGODB_URI`, `MONGODB_DB`. Используйте прежнюю базу и имя БД, если нужно сохранить игроков, балансы и активные игры. Не отправляйте секреты в чат и не добавляйте `.env` в Git. После настройки:

```sh
npm start
```

В панели запуска выберите Node.js 24, рабочую папку с `bot.mjs` и команду `npm start`. Она не запускает компилятор и не требует devDependencies. Если панель запускает файл напрямую: `node --env-file-if-exists=.env bot.mjs`.

В Atlas проверьте, что кластер активен, в Network Access разрешён исходящий IP хостинга, а база поддерживает транзакции (replica set/Atlas). Данные и очереди находятся в MongoDB, не в файлах приложения. Сборка в один файл не устраняет сетевые ошибки MongoDB или ограничения VK.

## Обновление

1. Соберите новую версию локально/в CI: `cd backup`, затем `npm ci` и `npm run build:hosting`. Эта команда обновляет корневой `bot.mjs`, рабочие файлы и `archives/kreox-hosting.tar.gz`. Для архива нужен `tar` (например, Linux/WSL/macOS).
2. Остановите старый процесс перед запуском нового, особенно при переезде с другого сервера.
3. Замените шесть файлов из нового архива, **сохраните свою `.env`** и прежнюю базу.
4. Выполните `npm ci --omit=dev` и запустите `npm start`.

Рекомендуется один процесс Long Poll для одного токена. При остановке отправляйте SIGTERM/SIGINT и давайте процессу штатно завершиться; не удаляйте БД/очереди. Настройте автоматический перезапуск средствами панели хостинга.

Архив содержит только пустой шаблон `.env.example`; настоящий `.env`, установленные зависимости, тесты и отладочные исходники в него не входят. Ничего не редактируйте в сгенерированной папке `hosting/`: следующая сборка пересоздаёт её. Правки делаются в `backup/src`, затем запускается новая сборка из `backup/`. Корневой `npm start` запускает готовый `bot.mjs` без сборки.


## Кости в беседах

- `кости` — показать активные игры, каждую отдельным сообщением; если игр нет — `Костей нет.`
- `кости 1000` / `кости 10кк 3` — KC, минимум 1.000 KC.
- `кости евро 10` / `кости донат 10 4` — евро, минимум 10 💶.
- `кости бит 10` / `кости биткоин 10 5` — биткоины, минимум 10₿.
- Вместо суммы: `все` / `всё` / `вб` — весь доступный баланс выбранной валюты, `пол` — половина: для KC округление до целой монеты, ровно 0,5 вверх; для евро/BTC — вниз до минимальной единицы валюты. Сумма определяется в транзакции перед списанием, затем проверяются минимум и предел банка. Например: `кости пол 3`, `кости евро всё`, `кости бит вб`.
- Без последнего числа — 2 места; допустимо 2–5 игроков, до 5 активных игр в одной беседе.
- Зелёная `Играть` списывает такую же ставку, красная `Отмена` возвращает ставку и освобождает место. Создатель выходит только сам; когда участников нет, игра удаляется.
- После заполнения каждому независимо выпадает от 1 до 12. Один победитель получает 99% банка; при равном максимуме лидеры делят 96,55% банка. Комиссия и неделимый остаток начисляются администратору 888801846 в валюте игры. Дополнительных выплат директору/крупье нет.
- Номер игры растёт отдельно для каждой беседы. После завершения старые кнопки молчат.
- 30 минут отсчитываются от создания и не продлеваются входами/выходами. По истечении бот пишет в беседу, ставки возвращаются, участникам отправляются ЛС, если они разрешены.
- Если баланс не вмещает возврат/выигрыш, начисление остаётся в надёжной очереди MongoDB и повторяется после освобождения места. Уведомление о возвращённой по таймеру ставке отправляется после фактического зачисления. Если администратор ещё не зарегистрирован, его комиссия также ждёт регистрации.

Таймеры и выплаты восстанавливаются после перезапуска; не удаляйте `casino_records`, `processed_messages` и `notifications`. Новых обязательных ENV и сторонних зависимостей для костей нет.

## Разработка и проверки

В `backup/` сохранены исходники, тесты, TypeScript-настройки, lockfile и сборщик. Для разработки нужен Node.js 24:

```sh
cd backup
npm ci
npm run typecheck
npm test
npm run build
npm run test:integration
npm run build:hosting
```

Интеграционные тесты требуют отдельного MongoDB replica set через `MONGODB_TEST_URI` и создают временные тестовые базы. Без переменной они пропускаются; не указывайте рабочую базу. Полная история правил приложения находится в `backup/README.md`.

## Административные раздачи

Только в беседах, запуск и отмена — только администраторы из существующего списка (сейчас 888801846):

```text
/force Раздача кейс реферальный 10 10
/force Раздача кейс ждун 10 1
/force Раздача крупьер 10 1
/force Раздача монеты 10 10кк
/force Раздача евро 10 100
/force Раздача биткоин 10 100к
```

Предпоследнее число — число получателей, последнее — награда **каждому**. Валютные суммы поддерживают к/кк, предметы — 1–1000 единиц каждому, как существующая выдача предметов. Награды создаются административной командой, деньги/предметы администратора не списываются; отмена не создаёт ему невыданный остаток.

Зелёная `Получить` начисляет награду и расходует одну активацию в одной транзакции MongoDB. Игрок может получить награду один раз; администратор тоже может участвовать. Если игрок ещё не зарегистрирован, регистрация и получение происходят за одно нажатие. При переполнении баланса/инвентаря награда и активация не расходуются — можно повторить попытку, пока раздача актуальна. Красная `Отмена` доступна только администратору и показывает число получателей и награду каждому; уже выданное не забирается.

В каждой беседе своя текущая раздача. Новая делает старые кнопки неактуальными только в той же беседе. У старой раздачи приоритетно показывается предупреждение о старой; у завершённой/отменённой текущей — `⚠ Раздача закончилась.`; повторное получение в активной раздаче — `⚠️ Вы уже получали награды с этой раздачи!`. Последний получатель видит `Раздача завершена!`. Отдельного тайм-аута у раздач нет.

Состояние и отметки получателей сохраняются в `casino_records`, повторная доставка события и перезапуск не выдают награду повторно. Используются существующие индексы `_id`, новых обязательных ENV, зависимостей и сбросов балансов нет. Обновлённые `bot.mjs` и `archives/kreox-hosting.tar.gz` собираются из `backup/` командой `npm run build:hosting`.

## Быстрый ответ и немедленная обработка очереди

- Награда подтверждается только после успешного коммита MongoDB. Списания, версия игры, отметка получателя и защита повторов не заменены кэшем или ответом «заранее».
- Проверка получения раздачи использует два точечных чтения (текущая раздача и отметка игрока) вместо пяти. Подготовленное состояние используется только внутри той же транзакции; при повторе транзакции оно читается заново.
- В обычном ЛС исключён отдельный запрос времени для вступления в аудиторию рассылок: MongoDB ставит `joinedAt` через `$$NOW` в операции записи, прежняя дата не меняется. Повтор уже обработанного события возвращается до повторных записей аудитории.
- Новые уведомления немедленно будят отправку после коммита: результаты и списки костей, подарки, переводы, реферальные уведомления. Завершённые банковские вклады тоже будят очередь. Чтение профиля не запускает лишний опрос очереди.
- Сигнал во время уже работающей отправки не теряется: после текущей партии очередь проверяется снова. Одновременно работает один отправитель; резервный интервал восстановления и задержки повторов при ошибках сохранены. Низкий приоритет рассылок не изменён.
- Запись реестра бесед идёт параллельно обработке сообщения, а не перед ответом. Она всё ещё учитывается при штатном завершении. Начальное заполнение реестра перед запуском и периодическое обновление сохранены для корректной рассылки игровых объявлений.

«Немедленно» означает отсутствие дополнительного ожидания тика очереди после нового коммита, а не гарантированные 0 мс: остаются доставка Long Poll, сеть, транзакция MongoDB, очередь и ограничения VK. Лимит API 20 запросов/с, группировка до 25 отправок в execute, повтор с тем же random_id и тайм-ауты не ослаблены. Фактическое время ответа на вашем хостинге этими тестами не измеряется.

## Защита обычных сообщений и снижение нагрузки MongoDB

Сокращённая рулетка распознаётся только как две части: допустимая цель и допустимая ставка не ниже минимума либо `все`/`всё`/`вб`/`пол`. Фразы `5 минут`, `10 человек`, ошибочная сокращённая ставка и лишние слова не вызывают подсказку. Полная команда `рулетка …` по-прежнему сообщает об ошибках и минимуме.

Лимиты баланса, предметов или числа приглашённых у реферера больше не мешают регистрации новичка: награда не начисляется ни полностью, ни частично. Позднейшего автоматического доначисления нет. Настоящая ошибка записи БД по-прежнему откатывает всю транзакцию, включая регистрацию и награду.

- ID ответов и уведомлений резервируются у `counters.responses` блоками по 256 с подтверждением `majority`, без участия этого счётчика в экономической транзакции. Между экземплярами бота блоки не пересекаются; откат или перезапуск оставляет пропуски номеров, но не возвращает их в оборот. Повторы отправки используют сохранённый ID. Последний блок ограничен максимумом VK, переполнения и перехода через ноль нет. **Не обнуляйте счётчик `responses`.**
- `store.now()` читает серверное время только при первом обращении в конкретной попытке транзакции. Повтор транзакции получает новое время; возвращаемые даты независимы от изменения их вызывающим кодом. Локальные часы вместо MongoDB не используются.
- Реестр бесед кэширует одинаковое состояние на 60 секунд, максимум для 10 000 бесед. Изменение `active` проходит без ожидания TTL; записи одного чата упорядочены, чтобы исключение бота и повторное вступление не терялись из-за параллельных запросов. Ошибка записи сбрасывает запись кэша. Это только служебные метаданные, не кэш денег или игровых выплат.

Правило накопительного счёта сохранено: завершённые недели начисляются до операции; просмотр не сбрасывает дату, а успешное движение денег начинает отсчёт заново. Старая неделя пустого счёта и время до внесения новых денег не дают дохода новым средствам.

Общий TTL намеренно не добавлен. `processed_messages` сохраняет защиту от повторного экономического действия; `casino_records` содержит активные игры, состояние выплат и отметки получения. Даже завершённое уведомление может ещё проверяться игровым работником, поэтому его нельзя удалять только по возрасту. Для будущей очистки нужны отдельные правила завершения и зависимостей, а не удаление всей коллекции через N дней.

Новые ENV, зависимости, коллекции и индексы не требуются. Инициализация сохраняет существующие счётчики и данные; ручная миграция не нужна.

## Целые KC и закрытие ставок казино

KC — только целые монеты. Денежные результаты округляются до ближайшей монеты: `537,7 → 538`, `547,4 → 547`, ровно `537,5 → 538`. Округление применяется перед записью балансов и выплат, а не только в тексте. Например, баланс отображается как `1.803.947 KC`. Евро сохраняют сотые, BTC — сатоши; их прежняя точность и отображение не меняются. Коэффициенты вроде `x1.7` также не меняются.

Перед обновлением сделайте резервную копию БД и **остановите все экземпляры старой версии**. При запуске автоматически округляются KC кошельков, накопительных счетов, статистики краж и копилок крупье/директора. Миграция идёт ограниченными страницами с проверкой исходных значений; повторный запуск безопасен. Масштаб хранения не меняется: 1 KC по-прежнему кодируется числом 100, новые KC-суммы кратны 100. На верхнем безопасном пределе используется ближайшая допустимая целая сумма без переполнения. Не запускайте старую версию параллельно с новой.

Действующие старые ставки, депозиты, предложения, пулы выборов и сохранённые ответы не переписываются массово: денежная выплата округляется при исполнении. Исторические сообщения не редактируются задним числом. При продаже одна и та же округлённая цена списывается и начисляется; нулевая цена остаётся допустимой. В костях округлённые доли победителей и остаточная комиссия в сумме равны банку. Банковские комиссии и штрафы KC округляются отдельно; выплата равна сумме за вычетом округлённой комиссии/штрафа.

После истечения срока приёма поздняя ставка не списывает деньги и не вызывает отдельное сообщение `💰 Прием ставок завершен.`. Если фоновый обработчик ещё не закрыл раунд, обработка позднего сообщения атомарно закрывает его и ставит единственное стандартное объявление в очередь. Обработчик сообщений и фоновый работник используют одну операцию закрытия, версию раунда и одинаковый уникальный ключ уведомления. Повторы событий и одновременные попытки не создают новых объявлений. Это общее правило для рулетки, краша и дрима.

В объявлении две последовательные строки, без пустой строки между ними:

```text
🎰 Приём ставок для игры "Рулетка" закрыт.
🕒 Итоги раунда через 5 секунд…
```

Пятисекундный таймер результатов по-прежнему начинается только после завершения обработки уведомления отправителем. Ставки остаются закрыты до окончания выдачи результатов. В смешанном сообщении закрытая игра не мешает принятию допустимой ставки в другой игре.


## Дабл и общие ограничения ставок

Команда в беседе: `дабл <сектор> <ставка>`, например `дабл 50 100к`, `дабл 5 пол`. Секторы — **2, 3, 5, 50**. Поддерживаются `к`/`кк`, `пол`, `все`/`всё`/`вб`. Минимум **1.000 KC**, максимум **1.000.000 KC суммарно на одного игрока за раунд отдельной игры в отдельной беседе**. Этот максимум применяется также к рулетке, дриму и крашу. Во всех четырёх играх — максимум **10 ставок одного игрока в одном раунде**. Ранее принятые ставки не отменяются новым лимитом. Например, 600.000 + 400.000 KC разрешены; следующая ставка отклоняется с прежним сообщением о максимуме, даже на другой сектор. Бюджеты разных игроков, игр и бесед независимы; в следующем раунде бюджет начинается заново. Проверка использует принятые ставки внутри той же транзакции, поэтому несколько строк, повторные события и параллельные сообщения не обходят предел.

Один результат на раунд: веса x2/x3/x5/x50 — **75/50/30/3 из 158**, то есть около 47,47% / 31,65% / 18,99% / 1,90%. Выплата включает ставку: 1.000 KC на x5 → 5.000 KC. Отдача каждого сектора — 150/158, около 94,94%. Доход директора и крупье обрабатывается общей системой казино по прежним правилам.

Приём начинается с первой ставки: 10 секунд, каждая следующая принятая ставка продлевает собственный раунд на 0,5 секунды. После закрытия — 5 секунд до расчёта, отсчитываемых после обработки уведомления отправителем. Поздние ставки молчат и не списывают деньги. ## Суммарные ставки и компактные итоги казино

Для рулетки, дрима, дабла и краша 1.000.000 KC — общий бюджет принятых ставок одного игрока за один раунд, а не разрешение поставить эту сумму десять раз. Дополнительное ограничение в 10 ставок сохраняется. Отклонение не списывает KC, не начисляет доход должностям и не продлевает приём.

В результатах ставки одного игрока на одинаковый сектор/число/коэффициент объединяются в один блок. Например, четыре ставки по 1.000 KC на красное отображаются как одна ставка 4.000 KC и приз 8.000 KC. Разные игроки и разные цели не смешиваются. При нулевых потерях строки `💰 Проиграно: 0 KC` нет ни в одном из этих режимов.

Объединение не меняет деньги: приз в блоке равен сумме отдельных округлённых выплат. Каждая исходная ставка сохраняет свой уникальный ключ начисления; кредиты, отметки расчёта и блок результата записываются атомарно. Длинные итоги по-прежнему делятся на сообщения до 4096 символов, без обрезания победителей и без пустой строки в начале следующей страницы. Старые уже принятые ставки выше нового суммарного предела не отменяются и выплачиваются полностью.
