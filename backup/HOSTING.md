# Kreox: запуск на хостинге

Требуется хостинг с **Node.js 24**, npm, постоянным фоновым процессом и исходящим доступом к VK, MongoDB Atlas и `cdn.kleymorf.xyz`. Бот работает через Long Poll и не открывает HTTP-порт: выбирайте фоновый процесс/worker, а не веб-сервис с обязательным HTTP health check. Обычный статический хостинг/PHP или функция с коротким временем жизни не подходят.

## Что загружать

В корне репозитория уже находятся файлы для запуска. Либо распакуйте `archives/kreox-hosting.tar.gz`: внутри ровно шесть файлов. Папка `backup/` на хостинг не нужна.

- `bot.mjs` — вся логика приложения в одном собранном файле.
- `package.json` — зависимости и команда запуска, без сборки перед стартом.
- `package-lock.json` — зафиксированные производственные зависимости.
- `.env.example` — пустой шаблон настроек, не рабочие секреты.
- `.nvmrc` — версия Node.js.
- `README.md` — эта инструкция.

Исходники `backup/src`, тесты `backup/tests`, TypeScript и esbuild на хостинг загружать не нужно. Библиотеки mongodb/vk-io и их зависимости **не встроены** в `bot.mjs`: npm установит их в `node_modules`. Это не один полностью автономный файл без зависимостей.

## Первый запуск

В корне распакованной папки:

```sh
node --version
npm ci --omit=dev
cp .env.example .env
```

Перед `npm start` заполните `.env` **на хостинге** либо задайте переменные в его панели: `VK_TOKEN`, `VK_GROUP_ID`, `MONGODB_URI`, `MONGODB_DB`. Используйте прежнюю базу и имя БД, если нужно сохранить игроков, балансы и активные игры. Не отправляйте секреты в чат и не добавляйте `.env` в Git. После настройки:

```sh
npm start
```

В панели запуска выберите Node.js 24, рабочую папку с `bot.mjs` и команду `npm start`. Она не запускает компилятор и не требует devDependencies. Если панель запускает файл напрямую: `node --env-file-if-exists=.env bot.mjs`.

В Atlas проверьте, что кластер активен, в Network Access разрешён исходящий IP хостинга, а база поддерживает транзакции (replica set/Atlas). Данные и очереди находятся в MongoDB, не в файлах приложения. Сборка в один файл не устраняет сетевые ошибки MongoDB или ограничения VK.

## Обновление

1. Соберите новую версию локально/в CI: `cd backup`, затем `npm ci` и `npm run build:hosting`. Эта команда обновляет корневой `bot.mjs`, рабочие файлы и `archives/kreox-hosting.tar.gz`. Для архива нужен `tar` (например, Linux/WSL/macOS).
2. Остановите старый процесс перед запуском нового, особенно при переезде с другого сервера.
3. Замените шесть файлов из нового архива, **сохраните свою `.env`** и прежнюю базу.
4. Выполните `npm ci --omit=dev` и запустите `npm start`.

Рекомендуется один процесс Long Poll для одного токена. При остановке отправляйте SIGTERM/SIGINT и давайте процессу штатно завершиться; не удаляйте БД/очереди. Настройте автоматический перезапуск средствами панели хостинга.

Архив содержит только пустой шаблон `.env.example`; настоящий `.env`, установленные зависимости, тесты и отладочные исходники в него не входят. Ничего не редактируйте в сгенерированной папке `hosting/`: следующая сборка пересоздаёт её. Правки делаются в `backup/src`, затем запускается новая сборка из `backup/`. Корневой `npm start` запускает готовый `bot.mjs` без сборки.


## Кости в беседах

- `кости` — показать активные игры, каждую отдельным сообщением; если игр нет — `Костей нет.`
- `кости 1000` / `кости 10кк 3` — KC, минимум 1.000 KC.
- `кости евро 10` / `кости донат 10 4` — евро, минимум 10 💶.
- `кости бит 10` / `кости биткоин 10 5` — биткоины, минимум 10₿.
- Без последнего числа — 2 места; допустимо 2–5 игроков, до 5 активных игр в одной беседе.
- Зелёная `Играть` списывает такую же ставку, красная `Отмена` возвращает ставку и освобождает место. Создатель выходит только сам; когда участников нет, игра удаляется.
- После заполнения каждому независимо выпадает от 1 до 12. Один победитель получает 99% банка; при равном максимуме лидеры делят 96,55% банка. Комиссия и неделимый остаток начисляются администратору 888801846 в валюте игры. Дополнительных выплат директору/крупье нет.
- Номер игры растёт отдельно для каждой беседы. После завершения старые кнопки молчат.
- 30 минут отсчитываются от создания и не продлеваются входами/выходами. По истечении бот пишет в беседу, ставки возвращаются, участникам отправляются ЛС, если они разрешены.
- Если баланс не вмещает возврат/выигрыш, начисление остаётся в надёжной очереди MongoDB и повторяется после освобождения места. Уведомление о возвращённой по таймеру ставке отправляется после фактического зачисления. Если администратор ещё не зарегистрирован, его комиссия также ждёт регистрации.

Таймеры и выплаты восстанавливаются после перезапуска; не удаляйте `casino_records`, `processed_messages` и `notifications`. Новых обязательных ENV и сторонних зависимостей для костей нет.

## Разработка и проверки

В `backup/` сохранены исходники, тесты, TypeScript-настройки, lockfile и сборщик. Для разработки нужен Node.js 24:

```sh
cd backup
npm ci
npm run typecheck
npm test
npm run build
npm run test:integration
npm run build:hosting
```

Интеграционные тесты требуют отдельного MongoDB replica set через `MONGODB_TEST_URI` и создают временные тестовые базы. Без переменной они пропускаются; не указывайте рабочую базу. Полная история правил приложения находится в `backup/README.md`.
